## 3. 設計決策

### D23 — streak 計算是純函式，放 `engine.js`

`longestStreak(questions)` 與 `currentStreak(questions, upTo)` 皆為純函式，
輸入是既有的 `Question[]`，**不新增任何欄位到 `Question`**，不修改 `scoreQuiz()`。

**回傳資料契約（v4.1 新增，先寫死）：**

```
longestStreak(questions) → { length: number, hinted: number }
```

- `length`：最長連對段的長度
- `hinted`：**該段落內**（不是全卷）`mark === HINTED_MARK` 的題數
- 同長度的段落有多個時，取**最早出現**的那一段
- `currentStreak(questions, upTo)`：計算 `questions[0 .. upTo-1]`（**exclusive**）中
  末端的連對長度；只計已進入終態的題，未作答題不計入

**判定規則：**

| 情境 | 處理 | 理由 |
|---|---|---|
| 答對（未提示） | +1 | — |
| **答對（用了提示）** | **+1**，計入 `hinted` | 提示已在分數層扣過（1.0→0.5）。在 streak 再罰一次是雙重懲罰，會誘導使用者不敢用提示而硬猜——那正是本專案最怕的失效模式 |
| 答錯 | 歸零 | — |
| **作廢（`QState.VOID`）** | **跳過**：不 +1、不歸零 | 與 `scoreQuiz()` 排除 VOID 同一理由：作廢是資源載入失敗，不是使用者的作答。若中斷 streak，等於讓網路狀況決定成績表現 |

**為什麼不選另一個**：存成 `Question` 欄位（增量更新）會與 `state.questions` 形成第二份真相，
而遞補（`voidCurrent` 的 `push`）會改變陣列組成——增量值屆時已算錯且無從察覺。

### D24 — 稱號是一張二維表，表**就是**唯一真相

〔v4.1 依 verdict 2-3／2-4／4-1 重寫：移除 `rankValue` 序數〕

`rankTitle(level, score)` 為純函式，查一張**寫死的表**，不做任何計算、**不另建序數模型**。

```
                L1（簡單）      L2（中級）      L3（困難）
  ≥95           牌面熟手        對得很快        一眼認藥
  ≥80           記得住外觀      看得出門道      火眼金睛
  ≥50           還在對圖        還在比對        還在翻仕單
  <50           先從閃卡開始    先從閃卡開始    先從閃卡開始
```

**四條硬約束：**

1. **表是唯一真相**。驗收逐格斷言確切字串（A28），**不得**另建一個「等級序數」再去證明單調——
   序數可以任意指定，與使用者實際看到的字串沒有可證明的關聯，那是第二份真相。
2. **≥50 的 9 格各級不相交**，且**稱號永遠與級別徽章同框呈現**。
   〔v4.2 裁決〕`<50` 那一列三級**刻意共用同一句**，因此「不相交」與 A28 的
   「兩兩相異」都只約束 ≥50 的 9 格。理由：最低帶那句是**下一步建議而非稱號**，
   三級本來就該給同一個建議，且最低帶不存在「刷簡單級拿高階稱號」的誘因。
   A28 對這一列改用**正面斷言**（三格必須相同），避免日後被當成漏寫而各自改掉。
   不宣稱任何跨級的形式化排序——那是 D26 明文拒絕的東西。
3. **L1／L2 的稱號用字不得含精熟意涵**（黑名單與第 4 條共用）。
   這是第 2 條放棄形式化排序後，用來保住 D24 原始目的（防刷簡單級拿高階稱號）的
   較弱但可證偽的約束。
4. **封閉黑名單**：不得使用台灣有法定或認證意義的職稱。黑名單在規格與測試中**完整列出**，
   不以「等」代表開放清單；比對前套用正規化（大小寫、全半形、標點剝除）。
   完整稱號表另做一次**人工法規覆核並留檔**。

**視覺層級**：稱號的字級與對比**不得超過**既有的 熟練／尚可／待加強（`LEVELS[].pass`/`fair`），
DOM 順序位於其後。**稱號不進成績卡 PNG**（v4.1 新增，見下）。

**為什麼稱號不進成績卡**：成績卡是本工具唯一會外流的產物。威脅模型第二條就是
「誤導使用者高估自己的能力」——把趣味稱號印在可外流的 PNG 上是這條風險的最短路徑。
成績卡維持既有內容：級別、分數、亂猜基線、專業三級判定。

### D25 — 最佳紀錄的儲存契約

**唯一 key**：`tfda-drug-id-quiz:records`

單一 key 的理由是**schema 集中、清除簡單**——
〔v4.1 更正〕**不是**「原子性」：localStorage 不提供跨分頁交易，單一 key 也給不了原子性。

**值：**

```jsonc
{
  "schema": 1,
  "L1": {
    "bestScore":  { "value": 92.0, "date": "2026-08-03", "pool": "47f65fccc5d3" },
    "bestStreak": { "value": 14,   "date": "2026-08-03", "pool": "47f65fccc5d3" }
  },
  "L2": { ... },
  "L3": { ... }
}
```

**「有效紀錄」的完整 predicate**（v4.1 新增，依 verdict 1-6）——不符者該**難度**降級為無紀錄，
其他難度不受影響：

- `value` 為有限數（`Number.isFinite`）
- `bestScore.value` ∈ [0, 100]；`bestStreak.value` 為整數且 ∈ [0, 20]（上界由 F9 保證）
- `date` 符合 `^\d{4}-\d{2}-\d{2}$`
- `pool` 符合 `^[0-9a-f]{12}$`

**更新規則**：**只有嚴格大於才更新**。相等時不動（含 `date`／`pool`）——
相等就刷新日期會讓「最佳紀錄的日期」變成「最近一次打平的日期」，不是使用者預期的語意。

**兩條指標各自獨立更新**：`bestScore` 與 `bestStreak` 可來自不同回合。
最長連對不是分數的單調函式（19/20 但錯在第 10 題，連對短於 18/20 而兩題都錯在開頭者）。

**跨分頁一致性語意**（v4.1 新增，依 verdict 1-4）：
寫入前**重讀最新值**，對兩項各取 max 後再寫。
**這不消除競態**（localStorage 無交易），只把後果從「已創下的紀錄被倒退覆蓋」
降為「極短窗口內漏記一次」。**不引入** `storage` 事件監聽、`BroadcastChannel` 或任何鎖。

**七種失效情境**（v4.1 逐條編號，對應 C20–C22）：

| # | 情境 | 行為 |
|---|---|---|
| **E1** | `localStorage` 不存在／被停用 | 靜默降級：隱藏紀錄區塊，其餘完全照常 |
| **E2** | 讀取拋任何例外（不限 `SecurityError`） | 同 E1 |
| **E3** | 寫入拋任何例外（不限 `QuotaExceededError`） | 靜默吞掉，**且不得顯示「新紀錄！」**，不得中斷結算頁渲染 |
| **E4** | 讀到的值不是合法 JSON | 視為無紀錄。**在有新紀錄產生前不得執行任何 storage mutation**（`setItem`／`removeItem`／`clear`）；一旦有正常回合完成，該回合即為第一筆紀錄並有權覆寫 |
| **E5** | `schema !== 1` | 同 E4（含不遷移） |
| **E6** | 單一難度欄位缺漏／型別錯誤／不符 predicate | **只有該難度**視為無紀錄，其他難度原值保留 |
| **E7** | 使用者按「清除紀錄」 | 二次確認。**取消 → 零 mutation**；確認 → 只 `removeItem` 精確的 records key；移除失敗 → 不得顯示已清除 |

**「新紀錄！」提示的語意**（v4.1 新增，依 verdict 1-7）：
成功提示**只能在持久化確認完成後**顯示。E3 時不得顯示——
宣稱已保存而實際失敗，使用者要到下次開啟才發現紀錄不見了。

**`pool` 欄位的唯一用途**（v4.1 依 verdict 4-4）：**顯示**於紀錄區塊的診斷小字。
不參與比較、不做遷移。宣告了卻從未使用的欄位是純負擔——
v3.6 已因同樣理由移除過 `usedAns` 與 `slotAsset[]`。

### D26 — 不做任何跨級合併或跨題庫版本換算

沿用 v3 D14 的紀律。三級的 `pass`/`fair` 與亂猜基線都不同（25／25／0），

### D27 — 動畫紀律

〔v4.1 依 verdict 2-6／4-6 收斂範圍〕

**允許的動態效果，窮舉**：

1. 選項揭曉的**顏色／邊框** transition（120–180ms）
2. streak 數字的**單一 `transform: scale`** transition
3. 既有的 `button` background transition、`.bar > i` width transition

**不做 `@keyframes`**（已列非目標）。

**四條硬界線：**

1. **全部現存及新增的動態效果**皆置於 `@media (prefers-reduced-motion: no-preference)` 內
   （正向表列）。**含既有的兩條 transition**——reduced-motion 是使用者的無障礙偏好，
   對「哪些動畫是這批加的」不感興趣。
2. **不得延後任何資訊的呈現**。正解、判定文字、正解格標記、`btnNext`（含 `disabled` 狀態）
   必須在 `lockAndReveal()` 返回的**同一 tick** 就處在最終可見且可操作狀態。
   **不得**用 `setTimeout`、`queueMicrotask`、`requestAnimationFrame` 或 Promise 延後這些 DOM 更新；
   **不得**用 `opacity` 由 0 起、不得用 `visibility`。
3. **不得造成 document flow 位移**：只用 `transform` 與顏色，
   不動 `width`/`height`/`margin`/`padding`/`font-size`/`border-width`。
4. **驗證方式受 F13 限制**：CSS cascade 與 layout **不能**在現有 stub 上驗。
   拆為「靜態 CSS 原始碼契約（自動）」＋「真實瀏覽器人工留檔」兩層（見 C25／C27）。
5. 〔**v4.3 依 verdict-v4a CR-1／SC-1 新增**〕**動畫只能由 CSS 產生，JS 不得自帶**。
   `app.js` 不得出現 `behavior: 'smooth'`、`scrollIntoView({ behavior })`、`Element.animate()`、
   `requestAnimationFrame` 驅動的視覺補間。
   **理由**：條 1 的正向表列以 CSS `@media` 為載體，JS 端動畫繞過整套管控；
   為了保留單一捲動效果而在 JS 引入 `matchMedia` 分支，等於開第二套動畫管控機制。
   捲動一律用 `window.scrollTo(0, 0)`。**由 C25 的靜態契約強制**。

### D28 — 錯題再戰：兩階段，沿用 D19 的整卷模型

〔**v4.1 依 verdict 2-1／4-2 整段重寫**。原「逐鍵 API」方案已作廢〕

**錯題集合的定義**（精確，決定分母）：

> 本回合中 `state !== QState.VOID` **且** `correct === false` 的題目，取其 `item.ans`。

作廢題**不算**錯題（沿用 D23 同一理由）。用提示答錯的題**算**錯題。
由原卷的 H1 保證這組鍵兩兩相異。

**兩階段組裝**（與 D19 唯一的差別在第一階段）：

| 階段 | D19（正常卷） | D28（錯題卷） |
|---|---|---|
| 1. 決定整卷正解集合 | 從 eligible 隨機抽 n 個鍵 | **由錯題鍵固定**（不抽） |
| 2. 逐題組裝 | 以整卷正解集合為 `excludeAns` | **完全相同** |
| 3. 整卷驗證 | `validateQuizInvariants()` | **完全相同** |

**這不是新的組裝模型**。F14 已確認 `buildChoices` 具備 `excludeAns`；
逐鍵 API 只帶單一 `ans` 會讓前面題目的誘答等於後面題目的正解，**在建構期就違反 H2**。
v3 花了兩輪覆審才把第一套組裝模型弄對，不再開第二套。

**分級重建內容（依 F8）：**

| 級別 | 重建內容 | 依據 |
|---|---|---|
| **L1** | 同答案鍵；重抽誘答藥名、重抽選項順序（**正解格位置必須可變**）；圖片若該鍵有 >1 筆紀錄則一併重抽 | 位置記憶（「上次我選 B」）是真實風險 |
| **L2** | 同答案鍵；重抽誘答圖片、重抽選項順序（**正解格位置必須可變**）；正解格圖片若該鍵有 >1 筆紀錄則一併重抽 | 同上 |
| **L3** | 同答案鍵；紀錄若有 >1 筆則重抽，**否則沿用原圖** | L3 沒有選項，不存在位置記憶；F8 顯示 82.0% 的鍵只有 1 筆紀錄 |

**複習途中圖片載入失敗**（v4.1 新增，依 verdict 1-1）：
**整個複習中止並回到原成績**。
**嚴禁**沿用 `voidCurrent()` 的既有遞補——F15 已確認它抽的是任意未使用鍵，
複習卷用它必然混入原本沒答錯的藥，而畫面上完全看不出來。
（不採「同答案鍵重建」是因為那需要在複習模式再實作一套遞補路徑；
複習卷通常只有數題，中止的代價遠低於維護第二條遞補路徑。）

**重建失敗**（誘答組不出來、`INVARIANT_VIOLATED`）：**整卷中止**，
不得「把該題剔除後繼續」——沿用 v2「發布是全有全無」的同一紀律：
靜默剔除會讓使用者以為自己已複習完全部錯題。
中止時**原卷、目前模式與 DOM 必須完全不變**。

### D29 — 錯題卷不登錄紀錄、不給稱號、不出成績卡

錯題卷的分母不是 20、題目來源不是隨機抽樣（是刻意挑的難題子集）。

複習結算頁**只顯示**：本次 N 題答對 M 題、逐題檢討，並標示「錯題複習（不計入紀錄）」。
**不顯示**分數／稱號／基線，**不提供成績卡下載**。

**不得**在複習期間污染記憶體中的最佳紀錄狀態（否則下一個正常回合會把它寫進去）。

### D30 — 批次分開交付與驗收

批次 A（M1–M4）不觸碰抽題路徑。批次 B（M5）動整卷組裝與 session ownership。
混做的話，不變量違規無法歸因是「新組裝路徑寫錯」還是「UI 改動的副作用」。

### D31 — Session ownership：原卷快照與模式

〔v4.1 新增，依 verdict 2-5〕

現況 `finish()`（`app.js:868`）與 `downloadCard()`（`app.js:925`）都直接讀 `state.questions`。
M5 需要同時存在原卷與複習卷，因此必須先定義 ownership：

- `state.mode`：`'quiz' | 'retry'`
- `state.origin`：進入複習前的原卷**快照**（questions、quizLevel、結算衍生值）
- **原卷快照在整個複習期間不可被修改**
- 返回後，結算頁、逐題檢討、成績卡**一律由原卷快照重新衍生**，
  不得靠回填先前保存的 DOM 字串（那樣 C29 表面會過，成績卡仍讀到複習卷）

**只允許一層複習**（依 verdict 1-2）：複習結算頁**不再提供**「錯題再戰」。
遞迴複習會讓「原卷」變成一個堆疊，而 D29 規定複習卷不計分——第 3 層在語意上什麼都不是。
重複啟動須**冪等**；返回固定回到原回合結算頁。

### D32 — M1／M2 的可見 UI 契約

〔v4.1 新增，依 verdict 1-3／3-X。**這是本輪最重要的方法論修正**〕

v4.0 的 A23–A29 全是 engine 層證據，**沒有任何一條證明 streak 與稱號真的接到畫面上**——
與上一輪「測試全綠、功能靜默不存在」是同一個形狀。

### 5.1 M1 streak（無持久化）

### 5.2 M3 最佳紀錄

```
進入 #start ─▶ readRecords() ─┬─ 有效 ─▶ 渲染紀錄區塊（含 pool 診斷小字）
                              └─ E1/E2/E4/E5 ─▶ 靜默隱藏區塊

                │                    ├─ 寫入成功 ─▶ 顯示「新紀錄！」
```

每一條新增測試都要做變異驗證（逐條回退實作、確認測試轉紅）。
**測不出來的要在測試檔註解誠實標明「此條未被行為測試守著」，不得假裝守住。**
靜態契約與人工留檔的條目，須在註解中標明其證據強度低於行為測試。
