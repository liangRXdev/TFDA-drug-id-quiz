## 3. 設計決策

### D23 — streak 計算是純函式，放 `engine.js`

`longestStreak(questions)` 與 `currentStreak(questions, upTo)` 皆為純函式，
輸入是既有的 `Question[]`，**不新增任何欄位到 `Question`**，不修改 `scoreQuiz()`。

**回傳資料契約（v4.1 新增，先寫死）：**

```
longestStreak(questions) → { length: number, hinted: number }
```

- `length`：最長連對段的長度
- `hinted`：**該段落內**（不是全卷）`mark === HINTED_MARK` 的題數
- 同長度的段落有多個時，取**最早出現**的那一段
- `currentStreak(questions, upTo)`：計算 `questions[0 .. upTo-1]`（**exclusive**）中
  末端的連對長度；只計已進入終態的題，未作答題不計入

**判定規則：**

| 情境 | 處理 | 理由 |
|---|---|---|
| 答對（未提示） | +1 | — |
| **答對（用了提示）** | **+1**，計入 `hinted` | 提示已在分數層扣過（1.0→0.5）。在 streak 再罰一次是雙重懲罰，會誘導使用者不敢用提示而硬猜——那正是本專案最怕的失效模式 |
| 答錯 | 歸零 | — |
| **作廢（`QState.VOID`）** | **跳過**：不 +1、不歸零 | 與 `scoreQuiz()` 排除 VOID 同一理由：作廢是資源載入失敗，不是使用者的作答。若中斷 streak，等於讓網路狀況決定成績表現 |

**為什麼不選另一個**：存成 `Question` 欄位（增量更新）會與 `state.questions` 形成第二份真相，
而遞補（`voidCurrent` 的 `push`）會改變陣列組成——增量值屆時已算錯且無從察覺。

### D24 — 稱號是一張二維表，表**就是**唯一真相

〔v4.1 依 verdict 2-3／2-4／4-1 重寫：移除 `rankValue` 序數〕

`rankTitle(level, score)` 為純函式，查一張**寫死的表**，不做任何計算、**不另建序數模型**。

```
                L1（簡單）      L2（中級）      L3（困難）
  ≥95           入門攻克        辨識高手        火眼金睛
  ≥80           記得住外觀      看得出門道      一眼認藥
  ≥50           還在對圖        還在比對        還在背藥名
  <50           先從閃卡開始    先從閃卡開始    先從閃卡開始
```

**四條硬約束：**

1. **表是唯一真相**。驗收逐格斷言確切字串（A28），**不得**另建一個「等級序數」再去證明單調——
   序數可以任意指定，與使用者實際看到的字串沒有可證明的關聯，那是第二份真相。
2. **≥50 的 9 格各級不相交**，且**稱號永遠與級別徽章同框呈現**。
   〔v4.2 裁決〕`<50` 那一列三級**刻意共用同一句**，因此「不相交」與 A28 的
   「兩兩相異」都只約束 ≥50 的 9 格。理由：最低帶那句是**下一步建議而非稱號**，
   三級本來就該給同一個建議，且最低帶不存在「刷簡單級拿高階稱號」的誘因。
   A28 對這一列改用**正面斷言**（三格必須相同），避免日後被當成漏寫而各自改掉。
   不宣稱任何跨級的形式化排序——那是 D26 明文拒絕的東西。
3. **L1／L2 的稱號用字不得含精熟意涵**（黑名單與第 4 條共用）。
   這是第 2 條放棄形式化排序後，用來保住 D24 原始目的（防刷簡單級拿高階稱號）的
   較弱但可證偽的約束。

   〔**v4.3 依 2026-08-06 人工覆核裁示補記**〕**「高手」不視為精熟意涵，「熟手」視為。**
   兩者字面接近，不記下區別理由的話下一輪覆審會再掃出來一次，因此明文寫死：
   - 「**熟手**」的「熟」直接指向**對該領域已熟練**，與黑名單的「熟練」同義，
     出現在 **L1（簡單級）最高帶**時正是本條要防的「刷簡單級拿高階稱號」。
     原 L1 ≥95「牌面熟手」因此改為「**入門攻克**」——「入門」把級別誠實寫進稱號裡。
   - 「**高手**」指向**相對他人的表現位階**，不宣稱能力已臻精熟；且出現在
     **L2（中級）**，該級的難度本身已排除「刷最簡單的拿高階稱號」這條路徑。
   黑名單維持封閉且**不**收錄「高手」——收了就與 L2 ≥95 的定案衝突。
4. **封閉黑名單**：不得使用台灣有法定或認證意義的職稱。黑名單在規格與測試中**完整列出**，
   不以「等」代表開放清單；比對前套用正規化（大小寫、全半形、標點剝除）。
   完整稱號表另做一次**人工法規覆核並留檔**。

**視覺層級**：稱號的字級與對比**不得超過**既有的 熟練／尚可／待加強（`LEVELS[].pass`/`fair`），
DOM 順序位於其後。**稱號不進成績卡 PNG**（v4.1 新增，見下）。

**為什麼稱號不進成績卡**：成績卡是本工具唯一會外流的產物。威脅模型第二條就是
「誤導使用者高估自己的能力」——把趣味稱號印在可外流的 PNG 上是這條風險的最短路徑。
成績卡維持既有內容：級別、分數、亂猜基線、專業三級判定。

### D25 — 最佳紀錄的儲存契約

**唯一 key**：`tfda-drug-id-quiz:records`

單一 key 的理由是**schema 集中、清除簡單**——
〔v4.1 更正〕**不是**「原子性」：localStorage 不提供跨分頁交易，單一 key 也給不了原子性。

**值：**

```jsonc
{
  "schema": 1,
  "L1": {
    "bestScore":  { "value": 92.0, "date": "2026-08-03", "pool": "47f65fccc5d3" },
    "bestStreak": { "value": 14,   "date": "2026-08-03", "pool": "47f65fccc5d3" }
  },
  "L2": { ... },
  "L3": { ... }
}
```

**「有效紀錄」的完整 predicate**（v4.1 新增，依 verdict 1-6）——不符者該**難度**降級為無紀錄，
其他難度不受影響：

- `value` 為有限數（`Number.isFinite`）
- `bestScore.value` ∈ [0, 100]；`bestStreak.value` 為整數且 ∈ [0, 20]（上界由 F9 保證）
- `date` 符合 `^\d{4}-\d{2}-\d{2}$`
- `pool` 符合 `^[0-9a-f]{12}$`

**更新規則**：**只有嚴格大於才更新**。相等時不動（含 `date`／`pool`）——
相等就刷新日期會讓「最佳紀錄的日期」變成「最近一次打平的日期」，不是使用者預期的語意。

**兩條指標各自獨立更新**：`bestScore` 與 `bestStreak` 可來自不同回合。
最長連對不是分數的單調函式（19/20 但錯在第 10 題，連對短於 18/20 而兩題都錯在開頭者）。

**跨分頁一致性語意**（v4.1 新增，依 verdict 1-4）：
寫入前**重讀最新值**，對兩項各取 max 後再寫。
**這不消除競態**（localStorage 無交易），只把後果從「已創下的紀錄被倒退覆蓋」
降為「極短窗口內漏記一次」。**不引入** `storage` 事件監聽、`BroadcastChannel` 或任何鎖。

**七種失效情境**（v4.1 逐條編號，對應 C20–C22）：

| # | 情境 | 行為 |
|---|---|---|
| **E1** | `localStorage` 不存在／被停用 | 靜默降級：隱藏紀錄區塊，其餘完全照常 |
| **E2** | 讀取拋任何例外（不限 `SecurityError`） | 同 E1 |
| **E3** | 寫入拋任何例外（不限 `QuotaExceededError`） | 靜默吞掉，**且不得顯示「新紀錄！」**，不得中斷結算頁渲染 |
| **E4** | 讀到的值不是合法 JSON | 視為無紀錄。**在有新紀錄產生前不得執行任何 storage mutation**（`setItem`／`removeItem`／`clear`）；一旦有正常回合完成，該回合即為第一筆紀錄並有權覆寫 |
| **E5** | `schema !== 1` | 同 E4（含不遷移） |
| **E6** | 單一難度欄位缺漏／型別錯誤／不符 predicate | **只有該難度**視為無紀錄，其他難度原值保留 |
| **E7** | 使用者按「清除紀錄」 | 二次確認。**取消 → 零 mutation**；確認 → 只 `removeItem` 精確的 records key；移除失敗 → 不得顯示已清除 |

**「新紀錄！」提示的語意**（v4.1 新增，依 verdict 1-7）：
成功提示**只能在持久化確認完成後**顯示。E3 時不得顯示——
宣稱已保存而實際失敗，使用者要到下次開啟才發現紀錄不見了。

**`pool` 欄位的唯一用途**（v4.1 依 verdict 4-4）：**顯示**於紀錄區塊的診斷小字。
不參與比較、不做遷移。宣告了卻從未使用的欄位是純負擔——
v3.6 已因同樣理由移除過 `usedAns` 與 `slotAsset[]`。

### D26 — 不做任何跨級合併或跨題庫版本換算

沿用 v3 D14 的紀律。三級的 `pass`/`fair` 與亂猜基線都不同（25／25／0），
合併成單一「最佳成績」等於製造一個統計假設不成立的可比較數字。
題庫更新後不清除、不換算，只存 `pool` hash 留痕（並顯示，見 D25）。

### D27 — 動畫紀律

〔v4.1 依 verdict 2-6／4-6 收斂範圍〕

**允許的動態效果，窮舉**：

1. 選項揭曉的**顏色／邊框** transition（120–180ms）
2. streak 數字的**單一 `transform: scale`** transition
3. 既有的 `button` background transition、`.bar > i` width transition

**不做 `@keyframes`**（已列非目標）。

**四條硬界線：**

1. **全部現存及新增的動態效果**皆置於 `@media (prefers-reduced-motion: no-preference)` 內
   （正向表列）。**含既有的兩條 transition**——reduced-motion 是使用者的無障礙偏好，
   對「哪些動畫是這批加的」不感興趣。
2. **不得延後任何資訊的呈現**。正解、判定文字、正解格標記、`btnNext`（含 `disabled` 狀態）
   必須在 `lockAndReveal()` 返回的**同一 tick** 就處在最終可見且可操作狀態。
   **不得**用 `setTimeout`、`queueMicrotask`、`requestAnimationFrame` 或 Promise 延後這些 DOM 更新；
   **不得**用 `opacity` 由 0 起、不得用 `visibility`。
3. **不得造成 document flow 位移**：只用 `transform` 與顏色，
   不動 `width`/`height`/`margin`/`padding`/`font-size`/`border-width`。
4. **驗證方式受 F13 限制**：CSS cascade 與 layout **不能**在現有 stub 上驗。
   拆為「靜態 CSS 原始碼契約（自動）」＋「真實瀏覽器人工留檔」兩層（見 C25／C27）。
5. 〔**v4.3 依 verdict-v4a CR-1／SC-1 新增；v4.4 依 verdict-v4b TG-7 收窄**〕
   **動畫只能由 CSS 產生，JS 不得自帶**。
   **理由**：條 1 的正向表列以 CSS `@media` 為載體，JS 端動畫繞過整套管控；
   為了保留單一捲動效果而在 JS 引入 `matchMedia` 分支，等於開第二套動畫管控機制。
   捲動一律用 `window.scrollTo(0, 0)`。

   **自動強制的部分——`app.js` 不得出現下列 API（明列，由 C25 的靜態契約掃描）**：

   | 契約樣式 | 涵蓋 |
   |---|---|
   | `behavior\s*:` | `scrollTo`／`scrollBy`／`scroll`／`scrollIntoView` 的平滑捲動選項（不綁特定方法名） |
   | `scrollIntoView\s*\(\s*\{` | `scrollIntoView` 帶選項物件 |
   | `\.animate\s*\(` | Web Animations API |
   | `requestAnimationFrame` | rAF 驅動的視覺補間 |

   **人工把關的部分**：`setInterval`／`setTimeout` 逐格改 `el.style.*` 這類
   計時器驅動的動畫**攔不到**，且無法靜態窮舉。
   〔TG-7〕原文寫成廣義宣稱（「JS 不得自帶動畫」）而只列出部分向量，
   等於承諾了契約做不到的事；追每一個向量會變成軍備競賽。
   因此**明列上表為自動強制的範圍，其餘由真實瀏覽器人工留檔把關**（同條 4 的兩層結構）。

### D28 — 錯題再戰：兩階段，沿用 D19 的整卷模型

〔**v4.1 依 verdict 2-1／4-2 整段重寫**。原「逐鍵 API」方案已作廢〕

**錯題集合的定義**（精確，決定分母）：

> 本回合中 `state !== QState.VOID` **且** `correct === false` 的題目，取其 `item.ans`。

作廢題**不算**錯題（沿用 D23 同一理由）。用提示答錯的題**算**錯題。
由原卷的 H1 保證這組鍵兩兩相異。

**兩階段組裝**（與 D19 唯一的差別在第一階段）：

| 階段 | D19（正常卷） | D28（錯題卷） |
|---|---|---|
| 1. 決定整卷正解集合 | 從 eligible 隨機抽 n 個鍵 | **由錯題鍵固定**（不抽） |
| 2. 逐題組裝 | 以整卷正解集合為 `excludeAns` | **完全相同** |
| 3. 整卷驗證 | `validateQuizInvariants()` | **完全相同** |

**這不是新的組裝模型**。F14 已確認 `buildChoices` 具備 `excludeAns`；
逐鍵 API 只帶單一 `ans` 會讓前面題目的誘答等於後面題目的正解，**在建構期就違反 H2**。
v3 花了兩輪覆審才把第一套組裝模型弄對，不再開第二套。

**分級重建內容（依 F8）：**

| 級別 | 重建內容 | 依據 |
|---|---|---|
| **L1** | 同答案鍵；重抽誘答藥名、重抽選項順序（**正解格位置必須可變**）；圖片若該鍵有 >1 筆紀錄則一併重抽 | 位置記憶（「上次我選 B」）是真實風險 |
| **L2** | 同答案鍵；重抽誘答圖片、重抽選項順序（**正解格位置必須可變**）；正解格圖片若該鍵有 >1 筆紀錄則一併重抽 | 同上 |
| **L3** | 同答案鍵；紀錄若有 >1 筆則重抽，**否則沿用原圖** | L3 沒有選項，不存在位置記憶；F8 顯示 82.1% 的鍵只有 1 筆紀錄 |

**「正解格位置必須可變」的精確語意**〔v4.5 依 verdict-v4b AR-7〕：
指的是**可達性**——同一鍵在不同 RNG 序列下，`answerIdx` 至少有 3 個值可達。
**不要求「必定不同於原卷的位置」**：那等於在組裝器加一個「排除原位置」的條件，
是改組裝模型（違反「不開第二套」）；而且 4 選 1 下強制必異只剩 3 種可能，反而更好猜。
因此本條**降低**位置記憶，不宣稱排除（§7 風險表措辭同步修正）。

### D28.1 — 原子發布點〔v4.5 新增，依 verdict-v4b AR-11〕

**「建構」與「發布」必須分開。** 候選卷在建構期間對使用者**完全不存在**：

> **發布點**＝候選卷完整建構 **且** `validateQuizInvariants()` 回傳空陣列 **且**
> 該級所需的資源前置條件成立（L2 的 ready-gate）。
> 在此之前，`state.mode` 不得改變、畫面不得切換、原結算頁不得被觸碰。

這樣一來，發布前的任何失敗都是「**還沒開始**」而不是「回滾」——
不需要第二套回滾狀態流程，也讓 A34／C35 的斷言有明確的比較基準。

**三種失敗的統一處置**：

| 失敗 | 時點 | 處置 |
|---|---|---|
| 重建失敗（誘答組不出來） | 發布前 | 不發布 |
| `validateQuizInvariants()` 回傳**任何**非空違規 | 發布前 | 不發布 |
| 複習途中圖片載入失敗 | **發布後**（答題中） | 整次複習終止，回到原結算 |

前兩者**不得**「把該題剔除後繼續」——沿用 v2「發布是全有全無」的同一紀律：
靜默剔除會讓使用者以為自己已複習完全部錯題。

第三者**嚴禁**沿用 `voidCurrent()` 的既有遞補——F15 已確認它抽的是任意未使用鍵，
複習卷用它必然混入原本沒答錯的藥，而畫面上完全看不出來。
（不採「同答案鍵重建」是因為那需要在複習模式再實作一套遞補路徑；
複習卷通常只有數題，終止的代價遠低於維護第二條遞補路徑。）

**失敗後的可觀察狀態**〔v4.5 依 verdict-v4b AR-4／AR-8〕
——三種失敗**一律**收斂到同一個基準：

> **等同「這一次複習從未啟動」的原結算狀態。**
> 逐項：`state.origin` 未變、`state.mode === 'quiz'`、
> retry 暫態（候選卷、部分建構結果、事件監聽）全部清除、
> **原結算頁的內容**（分數、稱號、三級判定、逐題檢討、成績卡按鈕）逐欄未變、
> 且「錯題再戰」控制項回到**可再次啟動**的狀態。

**唯一允許的例外**：一個**不觸碰原成績內容**的非破壞性失敗提示。
原文寫「DOM 完全不變」是自相矛盾的——使用者按了按鈕卻什麼都沒發生，
與「功能靜默不存在」無法區分，而那是本專案第二順位風險。
因此把約束精確化為「**原成績內容**不變」而非「DOM 不變」。

### D29 — 錯題卷不登錄紀錄、不給稱號、不出成績卡

錯題卷的分母不是 20、題目來源不是隨機抽樣（是刻意挑的難題子集）。
**任何跨回合可比較的數字都不適用於它**——這與 D26「三級分數不可互相比較」是同一條理由。

**N 與 M 的定義**〔v4.5 依 verdict-v4b AR-6〕：

> **N** ＝ 錯題卷的題數 ＝ 錯題鍵集合 K 的大小。
> **M** ＝ 本次 `correct === true` 的**題數**。

**M 是題數，不是分數。** 正常卷的 `HINTED_MARK` 讓提示後答對計 0.5 分，
若 M 沿用加權值會出現「5 題答對 3.5 題」這種讀不通的句子。
提示後答對**照樣計入 M**（它就是答對了）。

**retry 沿用與正常卷相同的提示能力**（L2 可刪去一個錯項、L3 可要首字母＋字數）。
不另做限制：複習的目的是再認一次，不是再考一次。

**正面契約**——複習結算頁**只顯示**：
`本次 N 題答對 M 題`、逐題檢討、以及「錯題複習（不計入紀錄）」標示。

**負面契約**（逐項，每一項都要有對應驗收，見 C36）：

| 不得出現 | 理由 |
|---|---|
| 分數 | 分母不是 20，數字不可比 |
| 稱號 | D24 的表以 (level, score) 為輸入，錯題卷沒有合法的 score |
| 亂猜基線 | 同上，基線是對 20 題隨機卷而言的 |
| 成績卡下載按鈕 | 成績卡是唯一會外流的產物，不得帶著不可比的數字外流 |
| 「錯題再戰」控制項 | D31 只允許一層 |
| **live streak（M1）** | 〔v4.5 新增，見下〕 |

**retry 模式隱藏 live streak**〔v4.5 新增，依 verdict-v4b H-1〕：
D32 規定 live streak 在答題頁 header、每次 `lockAndReveal()` 後更新，
而 **retry 用的就是同一個答題頁與同一條 `lockAndReveal()`**——不明寫就會照跑。
錯題卷是刻意挑的難題子集，在上面顯示連對與正常卷不可比，
且會誘導使用者把它當成能力訊號。**retry 答題頁不顯示 live streak，
retry 結算頁不顯示最長連對。**

**不得**在複習期間污染記憶體中的最佳紀錄狀態（否則下一個正常回合會把它寫進去）。
「不污染」的精確定義見 C28：**storage mutation 次數為 0**，不是「前後快照相同」。

### D30 — 批次分開交付與驗收

批次 A（M1–M4）不觸碰抽題路徑。批次 B（M5）動整卷組裝與 session ownership。
混做的話，不變量違規無法歸因是「新組裝路徑寫錯」還是「UI 改動的副作用」。

### D31 — Session ownership：原卷快照與模式

〔v4.1 新增，依 verdict 2-5〕

現況 `finish()`（`app.js:868`）與 `downloadCard()`（`app.js:925`）都直接讀 `state.questions`。
M5 需要同時存在原卷與複習卷，因此必須先定義 ownership：

- `state.mode`：`'quiz' | 'retry'`
- `state.origin`：進入複習前的原卷快照
- **原卷快照在整個複習期間不可被修改**

**單一真相來源**〔v4.5 依 verdict-v4b AR-1。**這是本輪最重要的修正**〕：

原文同時寫「快照含**結算衍生值**」與「一律由快照**重新衍生**」——
兩者並存就有兩份真相，一旦分歧沒有仲裁規則，
結算頁、逐題檢討、成績卡可能各讀到不同來源。

> **`state.origin` 只保存原始欄位，不保存任何可重算的衍生值。**

| 欄位 | 存不存 | 理由 |
|---|---|---|
| `questions`（含每題的作答、`state`、`correct`、提示使用紀錄） | **存** | 原始事實，無法重算 |
| `quizLevel` | **存** | 原始事實 |
| 分數、稱號、三級判定、最長連對、亂猜基線 | **不存** | 全部可由上兩者重算。存了就是第二份真相 |
| 結算頁 DOM 字串 | **不存** | 回填 DOM 會讓 C29 表面通過，而底層原卷已被覆寫 |

返回後，結算頁、逐題檢討、成績卡**一律由 `state.origin` 重新衍生**，
走的必須是**與正常回合結算完全相同的那條路徑**——
另寫一條「返回專用」的衍生路徑等於開第二套結算模型。

**快照生命週期**〔v4.5 依 verdict-v4b AR-3〕：

| 時點 | `state.mode` | `state.origin` |
|---|---|---|
| 正常回合進行中 | `'quiz'` | `null` |
| 正常回合結算頁 | `'quiz'` | `null` |
| **發布點**（D28.1）通過的瞬間 | → `'retry'` | → 建立快照（此後唯讀） |
| 複習答題中／複習結算頁 | `'retry'` | 唯讀 |
| 按「返回原成績」 | → `'quiz'` | 用它重新衍生後**清除為 `null`** |
| 複習中止（三種失敗任一） | 維持／回到 `'quiz'` | 清除為 `null` |
| **開始下一個正常回合** | `'quiz'` | **必須為 `null`** |

**最後一列是實際會壞的路徑**：返回後不清 `origin`，
下一個正常回合的 `finish()` 若讀到殘留快照，成績卡就印上一回合的分數。
C29 只涵蓋「複習中」，涵蓋不到這條。

**狀態轉移**（每個轉移都必須有對應驗收）：

```
原結算頁(quiz) ──點「錯題再戰」──▶ 建構中(仍為 quiz，使用者不可見)
                                      │
                    ┌─ 失敗 ──────────┘
                    ▼                 └─ 發布點通過 ──▶ 複習答題(retry)
              回原結算頁(quiz)                              │
              origin=null                                   ▼
              ＋非破壞性失敗提示                      複習結算(retry)
                    ▲                                       │
                    └────── 點「返回原成績」────────────────┘
                              由 origin 重新衍生 → origin=null
```

**只允許一層複習**（依 verdict 1-2）：複習結算頁**不再提供**「錯題再戰」。
遞迴複習會讓「原卷」變成一個堆疊，而 D29 規定複習卷不計分——第 3 層在語意上什麼都不是。

**冪等分三個場景定義**〔v4.5 依 verdict-v4b AR-3〕：

| 場景 | 要求 |
|---|---|
| 建構中再次觸發（雙擊） | 第二次起為 **no-op**；不得啟動第二次建構、不得覆寫已建立的 `origin` |
| 複習答題中觸發（若控制項仍可及） | no-op |
| 複習結算頁 | 控制項**不存在**（不是 disabled——不存在才不會被程式化觸發） |

**任何情況下 `origin` 都必須是最初那個正常卷**，不得被第二次啟動覆寫。

### D32 — M1／M2 的可見 UI 契約

〔v4.1 新增，依 verdict 1-3／3-X。**這是本輪最重要的方法論修正**〕

v4.0 的 A23–A29 全是 engine 層證據，**沒有任何一條證明 streak 與稱號真的接到畫面上**——
與上一輪「測試全綠、功能靜默不存在」是同一個形狀。

| 項目 | 契約 |
|---|---|
| live streak 位置 | 答題頁 header，與既有 `qScore` 同列 |
| 更新時點 | 每次 `lockAndReveal()` 後（含答對、答錯、提示後作答）、每次 `voidCurrent()` 後 |
| VOID 後的顯示值 | **不變**（跳過語意的可見對應） |
| 0 與 1 的顯示 | `length === 0` 時隱藏整個 streak 元素；`>= 1` 時顯示 |
| 提示標記 | 結算頁的最長連對顯示為「最長連對 N 題（含 M 題提示）」；`M === 0` 時省略括號 |
| 結算頁位置 | 「最長連對」為 `resultMetrics` 內的一個 metric 卡 |
| 稱號來源 | 由**實際的** `quizLevel` 與 `score` 查表取得，不得為固定文字 |
| 紀錄區塊 | 起始頁；顯示三級各兩項的 `value`／`date`／`pool` |

### D33 — M5 的可見 UI 契約〔v4.5 新增，依 verdict-v4b AR-2／AR-28〕

**D32 存在的理由完全適用於 M5。** D32 開頭寫著「v4.0 的 A23–A29 全是 engine 層證據，
沒有任何一條證明 streak 與稱號真的接到畫面上」——
M5 現在處於**完全相同的狀態**：D28–D31 全是資料與狀態語意，
沒有一條說「錯題再戰這個控制項在哪、什麼時候出現」。

**UI 表面刻意極小**（不引入持久化、歷史清單或新的成績模型）：

| 元素 | 契約 |
|---|---|
| 「錯題再戰」控制項 | 原結算頁，與既有「再測一回」同列；**錯題數 > 0 時才存在**（零錯題時**不存在**，不是 disabled） |
| 控制項文字 | 須含實際錯題數，例：「錯題再戰（N 題）」——數字由實際 K 大小衍生，不得為固定文字 |
| retry 模式標示 | 複習答題頁與複習結算頁都必須有可見標示，使用者任何時候都看得出「這是複習，不計入紀錄」 |
| 複習答題頁 | 沿用正常答題頁版面；**隱藏 live streak**（D29）；題號顯示為 `i / N` 而非 `i / 20` |
| 複習結算頁 | 只有 D29 的正面契約三項；負面契約六項逐一不得出現 |
| 「返回原成績」控制項 | 複習結算頁；**唯一目的地是原回合結算頁**，不是起始頁 |
| 建構失敗提示 | 非破壞性、不觸碰原成績內容（D28.1）；須說明是「這次沒能組出複習卷」而非靜默 |

**可見性的驗證分兩層**（F13 的既有紀律）：

- **DOM 接線與 handler 行為** → 自動測試（樁上可驗）
- **控制項對真實使用者是否可見**（沒有被 CSS 永久隱藏、對比與觸控尺寸）
  → **靜態 CSS 原始碼契約 ＋ 真實瀏覽器人工留檔**

〔堵〕樁可以點擊一個 `display: none` 的元素。
「測試點得到」**不等於**「使用者看得到」——這是假綠燈的第三種形態。

## 5. 資料流

### 5.1 M1 streak（無持久化）

```
state.questions[] ──(純函式)──▶ longestStreak() → 結算頁 metric
                                currentStreak()  → 答題頁 header（D32 的更新時點）
      └── 遞補 push 後自動反映（不快取、不增量）
```

### 5.2 M3 最佳紀錄

```
進入 #start ─▶ readRecords() ─┬─ 有效 ─▶ 渲染紀錄區塊（含 pool 診斷小字）
                              └─ E1/E2/E4/E5 ─▶ 靜默隱藏區塊
                                 E6 ─▶ 只隱藏該難度

finish() ─▶ 若 mode === 'quiz' ─▶ 讀最新值 → 各項取 max → 嚴格大於才寫
                │                    ├─ 寫入成功 ─▶ 顯示「新紀錄！」
                │                    └─ E3 ─▶ 靜默；**不顯示「新紀錄！」**
```

**F13 的直接後果**：C23／C25／C27 **不能**寫成 stub 自動測試。
這不是妥協，是誠實——寫成自動測試只會產生一組永遠綠的假斷言，
比沒有測試更糟（會讓後人以為那條守住了）。

### 變異驗證（硬性）

每一條新增測試都要做變異驗證（逐條回退實作、確認測試轉紅）。
**測不出來的要在測試檔註解誠實標明「此條未被行為測試守著」，不得假裝守住。**
靜態契約與人工留檔的條目，須在註解中標明其證據強度低於行為測試。
