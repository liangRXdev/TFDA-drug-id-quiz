## 1. 目標與非目標

### 目標

藥師外觀辨識自我測驗的**純靜態單頁工具**：

1. 每回合從題庫隨機抽 **20 題**，每題呈現藥品實拍圖 + 結構化外觀描述
2. 使用者輸入**英文品名**作答，即時判定對錯
3. 卡關可按「提示」看首字母與字數，該題滿分由 1.0 降為 0.5
4. 20 題完成後產生總分與逐題檢討
5. 成績卡可下載為 PNG 圖檔

> **用語紀律（依 1-1）**：一律稱「**英文品名**」，即資料集官方欄位名。
> 不可稱「品牌名」——題庫中 `SODIUM BICARBONATE`、`PROPRANOLOL` 等為學名式品名而非品牌名，
> 寫「品牌名」會誤導使用者該輸入什麼。作答欄位須明示：*輸入官方英文品名的核心字串，
> 不需輸入藥廠名、含量與劑型*。

### 非目標（v1 明確不做）

| 不做 | 理由 |
|---|---|
| 成分／學名作答或顯示 | 資料集 42 無成分欄位，需 join 另一資料集，管線複雜度 ×2 |
| 使用者帳號、成績雲端保存 | 純靜態站無後端；成績卡下載已滿足留存需求 |
| **離線作答、Service Worker、PWA 安裝** | **（依 2-4／2-5／4-1 新增）** 離線不在目標內，卻連鎖產生快取版本錯配與「離線需預載 60MB 全題庫」兩項架構風險 |
| 排行榜、社群分享、多人對戰 | 與「自我測驗」核心無關 |
| 藥品查詢功能 | 已有 `TFDA-drug-info-search`，不重複造 |
| 錯題本 / 間隔重複複習 | 需持久化與演算法設計，列後續版本 |
| 四選一選擇題模式 | 已決定用純輸入；25% 亂猜命中率破壞鑑別度 |
| 液劑／顆粒劑／粉劑題目 | 糖漿瓶照片不構成外觀辨識練習 |
| 無刻字藥品題目 | 僅憑形狀顏色無法唯一辨識，題目不可解 |
| **人工逐筆審核題庫** | **（依 4-3 新增）** 3916 題人工審核逾數十小時，超出專案規模；可解性改以自動化規則保證（D4） |
| 手機拍照上傳辨識 | 需影像模型，完全不同的專案 |

## 3. 架構決策與理由

### D1 — 資料由 GitHub Actions 抓取，前端只讀自家檔案
**不選**：前端直接 fetch `data.fda.gov.tw`。
**理由**：實測帶 `Origin` header 即回 403，瀏覽器 fetch 必定失敗。

### D2 — 圖檔鏡像至 repo，不外連
**不選**：`<img src="https://mcp.fda.gov.tw/...">`。
**理由（三個獨立原因）**：(1) 單張最大 6MB，20 題最壞 >60MB；(2) 圖檔主機無 CORS，跨域圖片進 canvas 會 taint；(3) 對方有 WAF，公開站直打 .gov.tw 有被封鎖風險。
**成本**：WebP 壓縮 27×，約 3916 張共約 **58MB**，遠低於 GH Pages 1GB 上限。

### D3 — 答案鍵 = 正規化後的英文品名核心字串
原始形如 `"ABBOTT" ISOPTIN 40MG FILM COATED TABLETS`。正規化管線（建置期算好存入 pool；執行期對使用者輸入跑**同一函式**）：

```
0. Unicode NFKC 正規化（全形英數 → 半形）      ← 依 1-5 新增
1. 轉大寫
2. 去除引號包裹的廠商名（"ABBOTT" / 中文全形引號）
3. 去除括號註記 (TRAZODONE HYDROCHLORIDE)
4. 去除含量 40MG / 0.23 MG / 3mg/0.02mg / 10%
5. 去除劑型字詞 TABLETS/CAPSULES/FILM/COATED/F.C./S.C./S.R./SOFT…
6. 去除非英數字元、收斂空白
7. 去除殘留的裸數字（"Lenangio 5" → LENANGIO）
```

### D4 — 題庫資格條件（依 1-2 重寫）

「可解」不再等同「有刻字」，改為**四項全數成立**才入題庫：

| # | 資格條件 |
|---|---|
| Q1 | 形狀屬固體口服劑型（排除液劑／顆粒劑／粉劑／其他） |
| Q2 | 有圖檔連結，且鏡像資產通過解碼驗證 |
| Q3 | 答案鍵長度 ≥3 |
| Q4 | `標註一` 非空（有刻字） |
| **Q5** | **外觀判別特徵不與其他答案鍵衝突**（見下） |

**Q5 定義**：以 `(形狀集合, 顏色集合, 刻痕集合, 標註一, 標註二, 外觀尺寸)` 為判別鍵分群
（多值欄位以 `;;;` 拆分後排序去重、標註去空白轉大寫）。
**同一判別鍵對應到 2 個以上相異答案鍵時，該群組全部排除。**

| 篩選階段 | 剩餘 |
|---|---|
| 全部 | 6251 |
| Q1 排除非固體口服 | 5701 |
| Q2 排除無圖檔 | 5679 |
| Q3 排除答案鍵過短 | 5678 |
| Q4 排除無刻字 | 4086 |
| **Q5 排除外觀不可區分群組（83 組／170 題）** | **3916 ← v1 題庫** |

**為何 Q5 是 Blocker 級**：實測最壞群組為「圓形／白／無刻痕／標註 S」對應 **10 種不同答案**
（ALLOPRIM、AMIPHEN、CYPROHEPTADINE HCL、FLAMQUIT、PROMERAN…）。
藥師給出「對另一顆藥而言正確」的答案卻被判錯，會強化錯誤記憶——
這正是威脅模型第一順位風險。**寧可少 170 題，不可誤判為錯。**

### D5 — 答案鍵重複不排除，改為同卷去重 + 答案鍵均勻抽樣（依 1-7 補）
784 組答案鍵重複（IBUPROFEN ×20、PREDNISOLONE ×15…），不同藥廠外觀不同，各自都是合理題目。
**抽樣單位＝答案鍵**：先自相異答案鍵均勻抽 20 個，每個答案鍵再自其紀錄中均勻抽 1 筆外觀。
**不選**紀錄均勻抽樣——那會讓 IBUPROFEN 出現機率是單一品項的 20 倍，扭曲教育分布。

### D6 — 純靜態零建置，engine 與 UI 分離
- `engine.js` — 純函式（正規化、比對、抽題、計分），無 DOM 依賴，`node --test` 可直接測
- `app.js` — DOM 與事件
- 無 bundler、無 npm build step

### D7 — 成績卡用 Canvas 純程式繪製，不截圖 DOM
**不選**：html2canvas 之類的 DOM 截圖。成績卡**僅含文字與色塊，不含任何藥品圖片**。

### D8 — 資產鍵規則（依 2-2 新增）

**問題**：許可證字號本身唯一，但兩種直覺 slug 做法皆產生 27 組碰撞、54 筆錯配。

**規則**：`asset_key = sha1(許可證字號 的 UTF-8 位元組).hexdigest()[:16]`
檔名 `data/img/<asset_key>.webp`。

- **不可**由字號去除中文或只留數字產生
- 管線須斷言全題庫 `asset_key` 100% 唯一，否則 fail
- pool 中每筆同時保存 `id`（原始字號）與 `img`，驗證條件須證明兩者一對一

### D9 — 發布為全有全無，異常幅度需人工裁決（依 2-6／3-3／4-2 新增）

**不選**：Codex 建議的「全面改人工觸發」。維護者是臨床藥師，不會每月盯 CI，會導致更新長期停擺。
**改為條件式自動化**：

```
變動幅度在門檻內  → 自動發布
超出門檻          → 不發布，開 issue 附差異摘要，等人工裁決
```

**門檻**：相對上一成功版本，題庫筆數增減 > **±3%**，或單次移除 > **50 題**。

**全有全無**：抓取、解壓、schema、筆數、資產解碼——任一階段失敗，
**不產生任何 commit，正式 `data/` 維持上一成功版本**。
**嚴禁**用「剔除該筆」吸收暫時性下載失敗：

| 情境 | 處理 |
|---|---|
| 來源已移除該筆／該筆已無圖檔連結 | 合法移除，計入變動幅度 |
| 本次 HTTP 下載失敗（逾時、5xx、WAF） | **重試 3 次；仍失敗則整批發布失敗**，不得刪題 |

### D10 — 圖片內容變更偵測與資產生命週期（依 2-1／2-3／2-7 新增）

- pool 每筆保存 `src_sha256`（來源原圖位元組雜湊）。
- 增量模式判定重抓的條件為「新增 **或** URL 變更 **或** `src_sha256` 不符」，
  且每季一次 `--verify-all` 完整重抓比對，偵測 TFDA 原地換圖。
- **seed 不是獨立腳本**：與 CI 為同一管線的 `--full` 模式，共用篩選、正規化、轉檔、驗證規則。
  首批資料須通過全部 B 組驗收才能成為基線。
- **孤兒資產**：不再被任何 pool 項目引用的 `.webp` 於發布時刪除。
- **容量預算**：`data/img/` 工作樹上限 200MB；超過則 fail 並要求人工決策。

```
┌─ GitHub Actions（每月 1 日 + 手動；concurrency group 序列化）──────┐
│                                                                    │
│ 1. GET export/42/json                                              │
│    └─ 非 200 → fail                                                │
│ 2. 驗證回應確為合法 ZIP（非 WAF 錯誤頁、非截斷）                   │
│ 3. 解壓；依 schema 辨識資料檔（欄位含 許可證字號/英文品名/外觀圖檔連結）│

│    └─ 重試後仍失敗 → 整批 fail，不刪題                             │
│ 9. 驗證每張資產可解碼、為 WebP、非零位元組                         │
│10. 刪除孤兒資產；檢查容量預算                                      │
│11. 全部通過才寫入 data/ 並 commit（全有全無）                      │
└────────────────────────────────────────────────────────────────────┘
```

### pool.json 結構（依 1-3／3-10 加入頂層版本區塊）

```json
{
  "meta": {
    "schema": 1,
    "source": "TFDA 藥品外觀資料集 (opendata 42)",
    "source_version": "2026-07-27",     // 來源 ZIP 內含時間戳，非執行時間
    "content_hash": "sha256:…",          // 內容版本，冪等比對依據
    "count": 3916
  },
  "items": [{
    "id": "衛署藥製字第000075號",
    "ans": "SODIUM BICARBONATE",
    "full": "SODIUM BICARBONATE TABLETS \"F.Y.\"",
    "zh": "\"信東\"蘇打錠500公絲",
    "img": "img/3f2a9c1b7e5d4a08.webp",
    "src_sha256": "…",
    "shape": ["圓形"], "color": ["白"], "score_mark": ["無"],
    "size": "8", "mark1": "FY T061", "mark2": null
  }]
}
```

**冪等紀律（B5）**：`meta` 內**不得**寫入執行時間或 job id——只保存來源版本與內容雜湊，
否則來源未變時仍會產生 diff，與 B5 直接衝突。

## 6. 作答規則

### 6.1 輸入契約（依 1-5）

| 輸入 | 處理 |
|---|---|
| 空字串、僅空白 | **不受理送出**，不計為答錯，不改變題目狀態 |
| 長度 > 60 字元 | 前端截斷並提示 |
| 全形英數（ＩＳＯＰＴＩＮ） | NFKC 正規化為半形後受理 |
| 中文、非 Latin 字元 | 進入 normalize，剝除後若為空則同「空字串」處理 |

**長度定義（依 3-6）**：所有長度判斷一律以**去除全部空白後的答案鍵**字元數為準，
容錯門檻、提示字數、測試斷言三處共用同一定義。

### 6.2 判定

```
判對 ⟺ normalize(輸入) 與 answer_key 符合下列任一：
  (a) 完全相同
  (b) 去除所有空白後相同           K-MYCIN / KMYCIN / K MYCIN 皆可
  (c) 去空白後編輯距離 ≤1 且答案鍵去空白長度 ≥6
```

**(c) 門檻為何是 6**：`ISAN`／`ISAM`、`URIEF`／`URIED` 編輯距離皆為 1 但可能是不同藥。

**碰撞處理順序（依 3-5，固定規則，非「視情況調整」）**：

1. A4 若偵測到跨答案誤接受，**不調整全域門檻**
2. 改為對**涉及碰撞的個別答案鍵停用容錯**（該題僅接受完全相同）
3. 停用清單由管線產出並存入 pool，非人工維護
4. 調整後仍必須維持**跨答案誤接受數 = 0**

### 6.3 提示（依 1-6）

以**去空白答案鍵**為基準，顯示首字母 + 底線，並標示原始詞數：

```
SODIUM BICARBONATE  →  S _ _ _ _ _ _ _ _ _ _ _ _ _ _ _ _  (17 字元，2 個字)
ISOPTIN             →  I _ _ _ _ _ _                      (7 字元，1 個字)
```

用過提示該題滿分 1.0 → 0.5。

### 6.4 題目狀態機（依 1-4）

```
未作答 ──送出──→ 已鎖定（對／錯）
   │                    │
   ├──取提示──→ 已提示 ─┘         滿分降為 0.5
   │
   └──資源失敗──→ 作廢（不計分、不計入分母）
```

- **首次送出即鎖定**，不可重試。這是刻意的：允許重試等於允許窮舉，計分失去意義。
- 已鎖定後不可再取提示。
- 重複點擊送出**不重複計分**（狀態機在已鎖定時忽略送出事件）。
- 逐題檢討於全部 20 題完成後才顯示，避免中途洩題。

### 6.5 資源失敗（依 1-8）

圖片 404、decode 失敗或 pool 項目損毀時：

- **絕不計為答錯**
- 該題標記為「作廢」，**不計入 20 題分母**
- 自剩餘題庫遞補一題；遞補失敗次數 ≥3 則中止本回合並顯示明確錯誤狀態
- 成績卡標註作廢題數

### 6.6 計分

`總分 = Σ 各題得分 / 實際計分題數 × 100`（分母排除作廢題）。成績卡另記提示次數與作廢題數。

## 7. 驗收條件（可證偽）

### A. engine.js 單元測試（`node --test`）

| # | 條件 |
|---|---|
| A1 | 對題庫全 3916 筆執行正規化，答案鍵長度皆 ≥3、無 `null`／空字串 |
| A2 | **Gold set**：≥40 筆人工確認的「原始英文品名 → 期望答案鍵」映射，涵蓋全部命名型態（英文引號廠商、中文全形引號、括號成分註記、比例含量 `3mg/0.02mg`、裸數字尾、連字號、多字品名、品名本身含劑型字詞如 `SOFT`／`ORAL`）。**全數精確相符** |
| A3 | 比對：`isoptin`／`ISOPTIN`／`Ｉｓｏｐｔｉｎ`（全形）皆判對；`isopten` 判對；`isopt` 判錯 |
| A4 | 對全題庫兩兩檢查，**跨相異答案鍵的誤接受數 = 0**（固定 pass/fail）。若原始門檻下非 0，套用 6.2 停用清單後重驗仍須為 0 |
| A5 | 抽題**不變量**斷言（非隨機重跑）：任一輸出必滿足 20 題答案鍵互異、皆有資產路徑、皆屬題庫。**固定 seed 可重現**。邊界：可用答案鍵 0／19／20／21 個時分別為「拒絕開始」「拒絕開始」「恰好成卷」「正常」 |
| A6 | 計分：全對 = 100；全錯 = 0；10 對其中 4 題用提示 = 40；**含 2 題作廢時分母為 18** |
| A7 | 狀態機：已鎖定後再送出不改變分數；已鎖定後不可取提示；空輸入送出不改變狀態 |

### B. 資料管線

| # | 條件 |
|---|---|
| B1 | **發布原子性**：抓取／ZIP 合法性／schema／筆數／資產解碼任一失敗，**不產生 commit**，`data/` 位元組完全不變。含「HTTP 200 但內容非合法 ZIP」與「200 但為 WAF 錯誤頁」兩案 |
| B2 | ZIP 內資料檔以 **schema 辨識**（欄位比對）而非檔名；注入「0 個符合」與「2 個符合」的 fixture 時皆 fail，不得取第一個 |
| B3 | **變動幅度**：相對上一成功版本增減 > ±3% 或單次移除 > 50 題時不發布並開 issue。同時記錄來源總筆數與 Q1–Q5 各階段筆數 |
| B4 | `asset_key` 全題庫唯一（斷言 3916/3916）；**注入兩筆會碰撞的許可證字號 fixture 時管線必須 fail** |
| B5 | 每筆資產可解碼、實際為 WebP、長邊 ≤640、非零位元組；任一失敗 → 整批發布失敗。<br>〔**2026-08-06 依 verdict-v4a CR-2 精確化責任歸屬**〕「**可解碼**」由 `fetch-images.py` 的 `verify_asset()` 以 Pillow 完整 decode 證明——新寫出的每一張都驗，`--verify-all` 的季度全跑再對內容未變的既有檔案驗一次。`verify-data.mjs` 只驗**容器結構**（RIFF 長度、WEBP 標記、chunk header、尺寸），從不觸碰壓縮位元流，因此**不得**宣稱可解碼。原文未區分兩者，導致 `verify-data.mjs` 印出強於證據的結論 |
| B6 | **一對一驗證**：pool 每筆的 `img` 僅被自己引用；`src_sha256` 與鏡像來源相符。注入「兩個 id 指向同一資產」的 fixture 時必須 fail |
| B7 | 冪等：來源未變時重跑，`git diff` 為空（`meta` 不含執行時間） |
| B8 | 暫時性下載失敗（模擬 3 次 5xx）→ 整批 fail，**pool 筆數不得減少** |
| B9 | 孤兒資產於發布時刪除；`data/img/` 總量 ≤200MB，超過則 fail |

## 8. 已知風險

| 風險 | 應對 |
|---|---|
| `標註一` 資料髒（20 筆含 `mg`／小數點被替換為空白，如 `0 23 mg`） | 顯示時原樣呈現、不做語意解讀；僅作輔助資訊 |
| 正規化剝離掉品名本身的關鍵字（品名即 `SOFT`／`ORAL` 等） | A2 gold set 明確涵蓋此型態 |
| 題庫含已下市藥品 | 標示「資料為 TFDA 外觀資料集快照，非現行供應狀態」 |
| `--full` 模式需下載約 3916 張圖（約 1.5GB） | 同一管線的完整模式，分批續跑；須通過全部 B 組才成為基線 |
| Q5 排除 170 題後仍可能存在圖片實際難以分辨者 | 屬殘餘風險；作答判定已排除文字特徵衝突，圖片層差異由使用者判斷 |
| 圖片已含 mm 標尺，`外觀尺寸` 資訊重複 | 保留文字描述作為可及性與低畫質備援，且 Q5 需用它作判別 |
