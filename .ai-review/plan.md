## 1. 目標與非目標

### 目標

藥師外觀辨識自我測驗的**純靜態單頁工具**：

1. 每回合從題庫隨機抽 **20 題**，每題呈現藥品實拍圖 + 結構化外觀描述
2. 使用者輸入**英文品牌名**作答，即時判定對錯
3. 卡關可按「提示」看首字母與字數，該題滿分由 1.0 降為 0.5
4. 20 題完成後產生總分與逐題檢討
5. 成績卡可下載為 PNG 圖檔

### 非目標（v1 明確不做）

| 不做 | 理由 |
|---|---|
| 成分／學名作答或顯示 | 資料集 42 無成分欄位，需 join 另一資料集，管線複雜度 ×2 |
| 使用者帳號、成績雲端保存 | 純靜態站無後端；成績卡下載已滿足留存需求 |
| 排行榜、社群分享、多人對戰 | 與「自我測驗」核心無關 |
| 藥品查詢功能 | 已有 `TFDA-drug-info-search`，不重複造 |
| 錯題本 / 間隔重複複習 | 需持久化與演算法設計，列後續版本 |
| 四選一選擇題模式 | 已決定用純輸入；25% 亂猜命中率破壞鑑別度 |
| 液劑／顆粒劑／粉劑題目 | 糖漿瓶照片不構成外觀辨識練習 |
| 無刻字藥品題目 | 僅憑形狀顏色多數無法唯一辨識，題目不可解 |
| 手機拍照上傳辨識 | 需影像模型，完全不同的專案 |

## 3. 架構決策與理由

### D1 — 資料由 GitHub Actions 抓取，前端只讀自家檔案

**不選**：前端直接 fetch `data.fda.gov.tw`。
**理由**：實測帶 `Origin` header 即回 403，瀏覽器 fetch 必定失敗。這與既有通則一致（.gov.tw opendata 對雲端 IP 回 5xx，見 `tw-opendata-google-ip-block`）。

### D2 — 圖檔鏡像至 repo，不外連

**不選**：`<img src="https://mcp.fda.gov.tw/...">`。
**理由（三個獨立原因，任一都足以否決外連）**：

1. **流量**：單張最大 6MB，20 題最壞情況 >60MB。醫院 wifi 不可接受。
2. **截圖功能**：圖檔主機無 `Access-Control-Allow-Origin`，跨域圖片進 canvas 會 taint，`toDataURL()` 直接丟 `SecurityError`。同源鏡像一併解決。
3. **可用性**：對方有 WAF（403 證據）。公開站每位使用者都打 .gov.tw 有被封鎖風險，且工具會隨對方服務中斷而失效。

**成本**：實測 WebP 壓縮 27×，4086 張約 **60MB**，遠低於 GH Pages 1GB 上限。

### D3 — 答案鍵 = 正規化後的核心品牌名

原始 `英文品名` 形如 `"ABBOTT" ISOPTIN 40MG FILM COATED TABLETS`，不可能要求原字串輸入。

正規化管線（**建置期**執行，答案鍵預先算好存進 `pool.json`；執行期只對使用者輸入跑同一函式）：

```
1. 去除引號包裹的廠商名     "ABBOTT" / “國嘉” / 全形引號
2. 去除括號註記             (TRAZODONE HYDROCHLORIDE)
3. 去除含量                 40MG / 0.23 MG / 3mg/0.02mg / 10%
4. 去除劑型字詞             TABLETS/CAPSULES/FILM/COATED/F.C./S.C./S.R./SOFT…
5. 去除非英數字元、收斂空白
6. 去除殘留的裸數字         "Lenangio 5" → LENANGIO
```

**實測結果**：固體口服 + 有圖 = 5679 筆，正規化後過短（<3 字元）僅 **1 筆**。

### D4 — 題庫僅收「固體口服 + 有圖 + 有刻字標註」

| 篩選階段 | 剩餘 |
|---|---|
| 全部 | 6251 |
| 排除液劑／顆粒劑／粉劑／其他劑型 | 5701 |
| 排除無圖檔 | 5679 |
| 排除答案鍵過短 | 5678 |
| **排除無 `標註一`（無刻字）** | **4086 ← v1 題庫** |

排除無刻字者的理由：僅憑「圓形／白色／無刻痕」無法唯一辨識，題目不可解，會變成挫折而非練習。

### D5 — 答案鍵重複不排除，改為同卷去重

784 組答案鍵重複、共 1918 筆，幾乎全是學名藥同名（IBUPROFEN ×20、PREDNISOLONE ×15、DEXAMETHASONE ×12）。

**不排除**：不同藥廠的 IBUPROFEN 外觀不同，各自都是合理題目。
**改為**：抽題時保證同一份考卷內 20 題的答案鍵**互異**，避免出現三題答案都是 IBUPROFEN。

### D6 — 純靜態零建置，engine 與 UI 分離

沿用 `tx-ebm-calc` 的既有模式：

- `engine.js` — 純函式（正規化、比對、抽題、計分），無 DOM 依賴，`node --test` 可直接測
- `app.js` — DOM 與事件
- 無 bundler、無 npm build step，`index.html` 直接 `<script type="module">`

視覺沿用 `pharmacy-tool-style` skill 的設計 token。

### D7 — 成績卡用 Canvas 純程式繪製，不截圖 DOM

**不選**：html2canvas 之類的 DOM 截圖。
**理由**：多一個外部依賴、字型與版面還原度不穩、且若卡片含任何跨域圖片就 taint。純 Canvas 繪製（純文字 + 色塊）完全可控，`toBlob()` 必成功。

## 4. 平台限制

| 限制 | 影響 |
|---|---|
| GitHub Pages 純靜態，無後端 | 無帳號、無伺服器計分；一切在瀏覽器內完成 |
| GH Pages 站台 1GB / 月流量 100GB 軟上限 | 題庫圖檔預算 ≤ 200MB |
| `data.fda.gov.tw` 帶 Origin 即 403 | 資料抓取只能在 CI 端 |
| 圖檔主機無 CORS | 跨域圖片不可進 canvas |
| GitHub Actions 單 job 6 小時上限 | 首次 4086 張圖下載須可中斷續傳 |
| repo 檔案單檔 100MB 上限 | `pool.json` 須控制在數 MB（不內嵌圖） |
| 目標裝置含手機 | 版面須 responsive；圖檔須 lazy load |

## 5. 資料流

```
┌─ GitHub Actions（每月 1 日 + 手動觸發）─────────────────────┐
│                                                              │
│ 1. GET export/42/json                                        │
│    └─ 非 200 → 整個 job fail，不覆蓋既有檔案                 │
│ 2. 解壓 ZIP（glob `*.json`，不硬編碼 42_5.json）             │
│ 3. 驗證：筆數 ≥ 5000 且必要欄位存在                          │
│    └─ 不符 → fail，不產出                                    │
│ 4. 篩選 D4 → 正規化 D3 → 產出 data/pool.json                 │
│ 5. 對「新增或圖檔 URL 變更」者下載圖片                       │
│    ├─ 轉 WebP q78，長邊上限 640px                            │
│    ├─ 存 data/img/<許可證字號 slug>.webp                     │
│    └─ 下載失敗 → 該筆剔除出 pool，不留破圖                   │
│ 6. 有 diff 才 commit；產出變更摘要                           │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌─ 瀏覽器（純靜態）────────────────────────────────────────────┐
│ 載入 data/pool.json（僅中繼資料，數 MB）                     │
│  → 抽 20 題（答案鍵互異）                                    │
│  → 逐題 lazy load data/img/*.webp                            │
│  → 作答比對（engine.js）                                      │
│  → 計分 → Canvas 繪製成績卡 → toBlob → 下載 PNG              │
└──────────────────────────────────────────────────────────────┘
```

`pool.json` 每筆欄位：

```json
{
  "id": "衛署藥製字第000075號",
  "ans": "SODIUM BICARBONATE",
  "full": "SODIUM BICARBONATE TABLETS \"F.Y.\"",
  "zh": "\"信東\"蘇打錠500公絲",
  "img": "img/wsyz-000075.webp",
  "shape": ["圓形"], "color": ["白"], "score_mark": ["無"],
  "size": "8", "mark1": "FY T061", "mark2": null
}
```

## 6. 作答判定規則

```
判對 ⟺ normalize(使用者輸入) 與 answer_key 符合下列任一：
  (a) 完全相同
  (b) 去除所有空白後相同           K-MYCIN / KMYCIN / K MYCIN 皆可
  (c) 編輯距離 ≤ 1 且 answer_key 長度 ≥ 6
```

**(c) 的長度門檻為何是 6**：短名容錯會製造誤判——`ISAN` 與 `ISAM`、`URIEF` 與 `URIED` 編輯距離都是 1，但可能是不同藥。長度 ≥6 時單字元容錯的碰撞機率可接受。此門檻須以題庫實際碰撞數驗證（見驗收條件 A4）。

**提示機制**：顯示首字母 + 以底線表示字數，如 `S _ _ _ _ _ _ _ _ _ (10 字元)`。用過提示該題滿分 1.0 → 0.5。

**計分**：`總分 = Σ 各題得分 / 20 × 100`，成績卡另記提示使用次數。

## 8. 已知風險

| 風險 | 應對 |
|---|---|
| `標註一` 資料髒（實測 20 筆含 `mg`／小數點被替換為空白，如 `0 23 mg`） | 顯示時原樣呈現、不做語意解讀；僅作輔助資訊，不影響判定 |
| 正規化過度剝離導致答案鍵撞名 | A4 驗收條件強制檢查；碰撞者標記後人工排除 |
| 題庫含已下市藥品 | 明確標示「資料為 TFDA 外觀資料集快照，非現行供應狀態」 |
| 首次 CI 需下載 4086 張圖（約 1.6GB） | 首次以本機腳本 seed 後 commit；CI 只做增量 |
| 圖片本身已含 mm 標尺，`外觀尺寸` 欄位資訊重複 | 保留文字描述作為可及性（讀屏）與低畫質備援 |
