## 三個 Blocker

### 2.1 D38／D39 的短卷定義對 L1／L2 數學上不可能 — **接受**

**已回讀 `engine.js` 確認：**

```js
const needDistractors = (level) =>
  level === Level.L2 ? DISTRACTOR_COUNT : CHOICE_COUNT - 1;   // L2 → 5，L1 → 3
```

而 `buildChoices` 的 `excludeAns` 恆為**整卷正解集合**（不變量 H2）。
D39 寫「短卷正解鍵集合**恰等於**那 K 個鍵」，當卷長 = K 時 `excludeAns` 吃掉全部 K 個鍵，
**誘答一個都抽不到**。

| 級別 | 每題需要的卷外誘答鍵 | 短卷可行條件 |
|---|---|---|
| L1 | 3 | 卷長 ≤ K − 3 |
| L2 | 5（3 正式＋2 備援） | 卷長 ≤ K − 5 |
| L3 | 0 | 卷長 ≤ K |

**只有 L3 能讓卷長 = K。** 我的 A42（K=9／10／19／20 三級共用同一預期）與
A43（K=14、卷長 14）整組建立在這個矛盾上。

**這是 D38「不得以重複題或跨子集誘答救場」的直接後果**——我寫了那條禁令，
卻同時要求一個只能靠違反它才能達成的卷長。修法採 Codex 建議：**級別特定卷長**。

### 2.2 D34 仍不足以稱為不可變 wire contract — **接受**

五個缺口全部屬實：varint 種類／byte order／最大長度／overflow 未定；
**CRC-32 沒指定 variant**（polynomial、init、reflected、final XOR——只寫「CRC-32」
不足以跨實作一致）；decoder 終止條件未定；base64url 尾端未用 bits 未要求為零
（否則同一 body 有多個字串表示，破壞 canonical 唯一性）；`count=0` 合法性未定。

Codex 同時**否決了我擔心的兩件事**，判斷正確：`count` 用 uint16 與 D42 沒有容量衝突
（1800 字元容納的筆數遠低於 65535）；固定寬度 header 與 varint groups 混用本身沒問題。

### S-1（主持人自查）號碼段可以帶字母，codec 編不了 — **接受**

**Codex 未抓到，由主持人窮舉來源資料集發現。**

D34.2／34.3 假設「藥證字號 ＝ 前綴 ＋ 純整數」。實測來源 6295 列：

```
不符合者 4 筆：
  衛署藥輸字第R00063號   衛部藥製字第R00042號
  衛部藥製字第R00043號   衛部藥製字第R00048號
```

`parseInt('R00063')` → `NaN`。若實作照 D34 寫，這四筆會**靜默錯配或消失**，
正是本專案最怕的形態。

**修法**：把前綴表的「前綴」定義從「…字」擴充為「**…字第 ＋ 號碼段的非數字前置部分**」，
於是 `衛署藥輸字第R` 成為獨立 table entry。delta＋varint 結構完全不動，
只多一至二筆表項；而 **B13 已會在遇到未知前綴時中止管線**，未來若出現 `第S` 會被擋下。

**同時實測確認**：前導零正規化後**零碰撞**（D35.2 那條容忍是安全的）；
號碼範圍 1–62392，16 bits 足夠。

### 區塊 3 — 驗證策略缺口

| # | 判定 | 要點 |
|---|------|------|
| **A36** | **接受** | 只驗「解析」不驗 **wire index**——parser 認得 16 個字串，codec 的 index 11–15 仍可全錯。加：每個前綴釘住精確 canonical id，新增 index 至少一組獨立 wire golden vector。**「測試資料不得由受測 normalizer 自己導出」**這句要寫進規格 |
| **A38** | **接受** | **本輪最重要的測試性洞見**：「golden 字串直接由受測 encoder 產生後抄回測試」——那只是 round-trip 的變形，**沒有獨立 oracle 就不是 golden**。加：body bytes 與 payload 須由人工推導或第二來源確認；矩陣涵蓋多 group、multi-byte varint、0、最大合法號碼、新增前綴、CRC byte order |
| **A40** | **接受** | 分類極精準：**bit-flip 保留舊 CRC**（驗完整性）vs **grammar-invalid 重算正確 CRC**（驗 canonical validator）。否則 decoder 只實作 CRC、完全不實作 grammar，也會全部拋錯而全綠。另：我寫的「或分段抽樣」是逃生口，須刪除並釘死 mutation 數 |
| **A42** | **接受** | 隨 2.1。且單一 seed 的敵意子集可能只是碰巧——須用規格化的固定 seed 集合 |
| **B13** | **接受** | **對我 v5.2 新增條文的直接反擊，而且對**：我寫的 fixture 沒指定那筆未知前綴要被淘汰，**若它剛好存活，只掃 `pool.json` 的錯誤實作仍會通過**——完全沒堵住 v5.1 的真正失敗模式。加：fixture 必須刻意在 Q1–Q5 被淘汰、注入多筆並斷言精確筆數；並明定前綴抽取發生在 allowlist 驗證**之前** |
| **C43** | **接受** | 「虛假完成感通常發生在**狀態轉換後**，不是初始 fixture」——加同 session 內 K 隨 level 變、月更降級後 N/K 變的斷言。靜態 scanner 須有**反向 sentinel** 證明自己抓得到 direct hidden／ancestor hidden／各不可及屬性 |
| **C50** | **接受** | 「零 sink 呼叫」可能只是**惡意資料從未到達受測路徑**——須先斷言該 token 確實經真實 tokenizer 到達第三類與下載資料，再驗 sink。並須列出樁實際監控的完整 sink inventory ＋ 每種都有 sentinel |
| **C51** | **接受** | 留檔須含完整畫面、瀏覽器與 zoom、viewport、fixture identity、實際 N/K、**觸控目標的人工量測數值**（不得目測「看起來夠大」）。四張各自獨立 verdict |

## 結論

**需第三輪重審。**

2.1（短卷模型）與 2.2＋S-1（wire format）都動到**資料模型與不可變契約**，
4.1 改變了 payload 的語意集合。依 Step 5 規則，修訂為 v5.3 後必須再審一次。

**但收斂趨勢明確**：53 → 22 項，且 Codex 主動聲明大方向已成熟、
列出五項「最小動工門檻」。第三輪預期會是確認性質。

## 這一輪的通則

### 一、四次同型錯誤：從已處理的產物回推來源性質

| 我的假設 | 真相 | 錯在哪 |
|---|---|---|
| 前綴有 11 種 | **16 種** | 從 `pool.json` 的 3924 筆存活品項導出 |
| 針劑是 Q1 篩掉的 | **根本不在來源** | 從 `meta.stages` 的階段名推測 |
| 來源可能有重複 id | **零重複** | 沒查，只能假設 |
| 號碼段是純整數 | **4 筆帶字母** | 看 `pool.json` 的樣本 |

四次都是下載一次來源（476 KB、0.9 秒）就能解掉。
**通則：規格若對來源資料做出任何斷言，動工前先把來源抓下來窮舉一次——
尤其是要變成 wire format 的斷言。**

### 二、「規格文字強於任何合理實作能達成的範圍」已第四次

D10（增量判定含 `src_sha256` 不符）→ D27（JS 不得自帶動畫）→
v5.0 的 A40（無冗餘位元卻要求偵測任意竄改）→ v5.2 的 D44.1（三介面原子提交）。

**共同形態：我寫下一個聽起來嚴謹的保證，卻沒問「這個保證由誰提供」。**
localStorage、`history`、記憶體各有各的失敗模式，沒有共同 transaction——
這在寫下「原子」兩個字時就該問。
