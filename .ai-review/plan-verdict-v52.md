## 2. D56 重新決策（Blocker）

**採 Codex 方案②：probe 的 identity 升為 `level × 卷長`。**

| | 原 D56（重抽） | 方案①（決定性投影） | **方案②（每卷長 probe）** |
|---|---|---|---|
| 正確性論證 | 錯誤（前提不成立） | 需證明「投影後不變量仍成立」，且該證明要一直成立 | **不需要新論證**——消費的是真實組卷產物 |
| D38.3 保證 | 破壞（probe 成功、開始可能失敗） | 保留 | **保留** |
| `quizLen ∈ [11,19]` 時 | 每次都走重抽 | 每次都走投影 | 直接命中 |
| 成本 | 0 次額外組卷，但有失敗率 | 0 次額外組卷 | 每級最多 ＋1 次組卷 |

**成本上限是可接受的**：可選卷長集合為 `{L ∈ QUIZ_LENGTHS : L ≤ 該級上限}`，
所以 `quizLen = 20` 的級別 probe 2 次、`quizLen ∈ [10,19]` 的級別只有 10 可選故 probe 1 次。
最壞情況 3 級 × 2 ＝ 6 次組卷，只在載入院內清單時跑一次。

**方案②同時修正了我 D55 的一個違規**：我原本用 `quizLenFor` 的**算術上限**決定卷長選項可用性，
而 D38 開宗明義寫著「`eligibleKeys().size` 不是可用性證據……算術門檻只是便宜的前置拒絕，
真正的證據是實際組卷成功且 `validateQuizInvariants()` 回空」。
用算術上限去判卷長可用性，犯的是 D38 花整段改寫才修掉的同型錯誤。
方案②讓可用性回到「該 `(level, 卷長)` 格實際組得出卷」，與 D38.2 同構。

## 3. 紀錄結構重新決策（High A-3／S-2）

**不升 `RECORDS_SCHEMA`。** 改在現行 `schema: 1` 結構內新增卷長層：

```
{ schema: 1,
  easy: { bestScore, bestStreak,            // ← 維持原位＝20 題卷（不動一個位元組）
          byLen: { "10": { bestScore, bestStreak } } },
  mid: {...}, hard: {...} }
```

### 為什麼這比 schema:2 好

| | schema:2 ＋ 遷移 | **schema:1 ＋ `byLen`** |
|---|---|---|
| 舊版讀到新資料 | 回 `{}`（認為無紀錄） | **正常讀出 20 題紀錄**（`validRecord` 只挑 `bestScore`／`bestStreak`，多餘欄位不影響） |
| 舊版跑完一回合 | `cur[level]` 為空 → **任何分數都算破紀錄** → 20 題紀錄被改寫、10 題全失 | 只在真的破紀錄時更新頂層；**20 題紀錄語意完全正確** |
| 損失上限 | 全部 | 僅 10 題紀錄（舊版 `readRecords` 濾掉 `byLen`，寫回時不帶它） |
| 需要 migration 邏輯 | 是（A48／A49／A50／M2／M7 全繞著它） | **否**——舊資料天然就是「有 20 題格、無 10 題格」 |
| 可安全回滾 | 否 | **是** |

**代價**：結構不對稱，20 題在頂層而 10 題在 `byLen`。這個不對稱**反映的是真實歷史**
（20 題曾經是唯一卷長），不是設計失誤。第 6 節已明列「其他卷長」不在本輪範圍；
真要加 5／30 題時再統一結構，屆時舊版早已不在使用者手上。

**仍須守住的**：`byLen` 只是欄位不是新 key，E7「只移除一個精確 key」完全不變。

### 已知的殘餘損失（明列，不隱藏）

使用者若在新版存了 10 題紀錄，之後用**舊版**（快取／SW 未更新）跑完一回合並破了 20 題紀錄，
`byLen` 會被舊版的寫回抹掉。10 題紀錄消失、20 題紀錄正確。
這是可接受的：損失局限、方向單一、且不會產生**錯誤**的數字（只會少一筆），
不觸及本專案最高權重的「靜默失真」。
