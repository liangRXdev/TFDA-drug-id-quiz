## 4. 是否需要第三輪

**否，可進入實作。**

理由：本輪 High 全部是**既有方向內的補完**，不是方向更換——
R-1 是資料 predicate 的合法形狀補完（結構仍是 `schema:1 + byLen`，一個位元組都沒改）、
V-1／V-2 是驗收條文的可證偽性修補。Codex 自己的最終判定也是
「`schema:1 + byLen` 方向可接受，但必須先補『10 題是該難度唯一紀錄』這個合法狀態」。

**動工前的硬性前提**：修訂為 v5.2-r3 後，R-1 的第四態、V-1 的 identity 快照、
V-2 的 sentinel 必須先寫進驗收，才允許寫第一行實作。

## 5. 本輪最貴的一條

**V-1（A56 token 集合）與第一輪的 B-1（截斷破壞不變量）是同一個病：對既有程式碼的性質
憑印象斷言，沒去讀那一行。**

- B-1：斷言不變量對子集不封閉 → 沒讀 `validateQuizInvariants`
- L-1：斷言 `app.js:1213` 是結算頁分母 → 沒讀那一行
- R-8：斷言 D48 講的是「重用真實產物」→ 沒讀 D48
- V-1：斷言 token 集合能證明 identity → 沒讀 `token: i + 1`

四條全部發生在**同一份規格文件**裡，而且 R-8 與 V-1 是在我因 L-1 被抓包之後才寫下的。
memory 裡「對來源／既有檔案做斷言前，先去讀那份檔案」這條，**在本輪之前已記錄 7 次，
本輪一次再犯 4 次**。這條教訓的失效模式不是「忘記」，是「當下不覺得那是一個斷言」。

**可操作的形式**：規格文件裡每一處引用既有程式碼行號、常數語意或既有決策編號的句子，
都是一個待驗證斷言，寫下時就要附上該次實際讀取的證據，否則不得寫進文件。
