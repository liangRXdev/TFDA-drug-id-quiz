## 1. 範圍

現有「看圖 → 輸入英文品名」重新定位為**困難級**，新增兩級：

| 級別 | 代號 | 題型 | 作答 |
|---|---|---|---|
| 簡單 | `L1` | 看圖 + 外觀特徵 → **四個藥名擇一** | 點選 |
| 中級 | `L2` | 給藥名 → **四張外觀圖擇一** | 點選 |
| 困難 | `L3` | 看圖 + 外觀特徵 → 輸入英文品名 | 鍵入（現行） |

### 1.1 這推翻了 v2 的一項非目標，必須明講

v2 §1 非目標表寫著：

> | 四選一選擇題模式 | 已決定用純輸入；25% 亂猜命中率破壞鑑別度 |

這條**當時是對的，現在仍然是對的**——四選一的 25% 底線確實破壞鑑別度。
改變的是目標本身：v2 只有一種模式，鑑別度是唯一的品質指標；v3 有三級，
L1/L2 的用途是**低門檻入門與名稱→外觀的反向回憶**，不是鑑別度。

因此不是「推翻理由」，而是**接受該理由並隔離其後果**：見 D14。
v2 §9 後續版本已列「難度分級」，本增修即兌現該項。

### 1.2 明確不做

| 不做 | 理由 |
|---|---|
| 跨級合併總分、跨級排行 | 基線不同尺度，合併即無意義（D14） |
| 依級別調整題庫資格條件 Q1–Q5 | 三級共用同一 `pool.json`，`schema` 維持 `1` |
| 修改 `normalize()` / `judge()` / 答案鍵 | L1/L2 不經文字判定；**本次不得重跑 `build:pool`** |
| 誘答預先算好存進 pool | 會使 pool 膨脹且與抽題耦合；執行期算得完（§4.6） |
| L1/L2 的錯題本、連續作答統計 | 沿用 v2 非目標 |

## 3. 設計決策

### D11 — L1「簡單」來自誘答外觀差異，不來自刻字可讀

**曾考慮**：把簡單級定義為「刻字上就寫著品名縮寫」的題目（讀刻字即可對上名字），
這是唯一**不靠記憶就能解**的簡單化路徑。

**否決理由**：F3 實測只有 **6.8%** 的題目刻字含品名前 3 碼。以此定義，
L1 題庫只剩約 267 筆、相異答案鍵約 200 個——連玩幾回就重複，且它其實是
**另一種題型**（讀字練習）而非同一題型的簡單版。

**採用**：L1 的簡單來自**誘答與正解外觀明顯不同**——
形狀集合不相交**且**顏色集合不相交。已知該藥大致長相（圓白錠 vs 藍膠囊）即可排除，
不需精確記憶刻字。F1 實測 100% 覆蓋，無題庫損失。

> 附帶好處：這同時保證了唯一解。若誘答與正解外觀特徵相同，題目就有兩個合理答案。

### D12 — L2 的可解性條件是 Q5 的加嚴版（**須通過 G1 才定案**）

v2 的 Q5 保證「同一判別鍵 → 唯一答案鍵」，判別鍵含
`(形狀, 顏色, 刻痕, 標註一, 標註二, 外觀尺寸)`。

**Q5 不足以保證 L2 可解。** L2 使用者**只看得到圖，看不到特徵欄位**，
`外觀尺寸` 與 `刻痕` 在照片上是弱訊號（尺標需比對、刻痕淺）。
兩個答案鍵可能只差 `size` 一個值就通過 Q5，但四張圖擺在一起肉眼無從分辨。

**L2 判別鍵（加嚴，去掉弱訊號欄位）**：

```
L2key = (形狀集合, 顏色集合, squash(標註一), squash(標註二))
```

**硬條件**：同一題的**全部 5 個誘答與正解**，`L2key` 必須**兩兩相異**。

因為 L2 誘答刻意選「同形同色」，`L2key` 相異實際上
**退化為 `標註一/標註二` 必須不同**——**L2 的可解性完全押在刻字差異上**。

> **這是產品決策，不是可事後微調的參數。** 改成「要求顏色不同」會改變學習目標、
> 難度定位與 F2/A9 的全部基準。因此列為 §0 的 G1 gate：
> **未通過照片可辨識驗證前，D12 不算定案。**

### D13 — 選項的名稱碰撞排除

同一題的任兩個選項（含備援），若其答案鍵構成下列任一關係即**不得共存**：

1. **編輯距離 ≤1**（`SOLAXIN` / `BOLAXIN`、`PISTON` / `POSTON`）
2. **其一為另一的前綴**（F4 的 269 組，`COLD` / `COLDAN`）

**比較前處理（寫死，不得自行發明）**：

- 比較輸入一律為 `squash(ans)`——即 pool 內既有的答案鍵去除全部空白，**不再做其他處理**
- 答案鍵已由建置期 `normalize()` 產出（全大寫、無標點），**本次不得為此改動 `normalize()`**
- **完全相等由 H1 處理，不再計為前綴碰撞**（避免同一件事兩處判定而漂移）

**兩級的威脅路徑不同，理由須分開寫**：

| 級別 | 威脅路徑 |
|---|---|
| L1 | 四個**藥名並列**，使用者對兩個近似字無從分辨，只能猜；猜對被記為答對 → 強化錯誤記憶（v2 §6.2 `no_fuzzy` 的同一紀律） |
| L2 | 只顯示一個藥名，上述因果**不成立**。真正的問題是：提示名為 `SODIUM BICARBONATE`、誘答圖屬 `SODIUM BICARBONATE COMPOUND` 時，兩者是**名義上難以切割的同族產品**，使用者選誘答並非誤認外觀而是誤解題意 |

**注意**：此處**不重用** `meta.no_fuzzy` 清單。該清單是「該答案鍵在題庫中某處有碰撞」的
全域標記，用它會把大量無關的安全誘答一併排除。這裡要的是**同題內兩兩檢查**，
直接呼叫既有的 `editDistance(a, b, 1)`。

### D14 — 亂猜基線逐題計算，不是固定 25

**v3 原稿的錯誤**：寫「固定顯示亂猜基線 25」＋「淨高於基線 X 分」。
兩者數學上不相容——L2 用過提示後是**三選一且滿分 0.5**，純猜期望為
`0.5 × 1/3 ≈ 0.167`，不是 0.25。整卷基線取決於使用提示的題數。

**採用**：`chance` 是**逐題欄位**，在題目狀態上，於建題與提示時決定：

| 情境 | 逐題 `chance` |
|---|---|
| L1／L2 四選一、未提示 | `1.0 × 1/4 = 0.25` |
| L2 三選一、已提示（滿分 0.5） | `0.5 × 1/3 ≈ 0.1667` |
| L3 自由輸入 | `0` |
| 作廢題 | 不計入（同分子分母紀律） |

```
回合基線 = Σ 各計分題 chance / 實際計分題數 × 100
```

`scoreQuiz()` **只做加總，不需要知道 level**，既有參數與得分語意完全不變——
避免把級別 UI metadata 耦合進計分核心。

| 措施 | 內容 |
|---|---|
| 結果頁 | `70.0 / 100　（本回合亂猜基線 23.8，淨 +46.2）` |
| 成績卡 PNG | **標題列印級別、分數區塊印基線**。不得只印分數 |
| 逐題檢討 | L1/L2 增「你選的」欄 |
| 熟練度標籤 | 三級門檻不同（§6.3），不共用 80/50 |

**不做**：`(score - 25) / 75` 之類的「校正分數」。那會產生一個看起來可跨級比較、
統計假設卻不成立的數字——四選一的猜測行為不是均勻隨機（使用者會先排除明顯錯項再猜）。
誠實標示基線即可。

### D15 — 誘答一次產生 5 個且兩兩合法，備援替換因此無需重驗

**v3 原稿的問題**：只說「預抽 3 誘答 + 2 備援」，沒定義備援彼此、
備援與誘答之間是否也要滿足同題條件。逐格替換會衍生
「重複消耗備援、留下重複 `ans`、`answerIdx` 與畫面錯位、提示刪到已換走的項目」等一串併發問題。

**採用**：一次產生 **5 個誘答**，要求
**這 5 個與正解、以及 5 個彼此之間，全數兩兩滿足 H1／H3 與（L2）`L2key` 相異**。

> 於是「**任取 3 個必合法**」成為結構性保證。替換時無須重新驗證任何條件，
> 原子性問題自然消失——這是消除複雜度，不是管理複雜度。

- 前 3 個為正式選項，後 2 個為備援
- **`spares` 僅 L2 使用；L1／L3 恆為空陣列**
- 「預抽」**不等於**「預載圖片」——備援圖片不預先請求

**替換規則**：

```
正解圖載入失敗            → 該題作廢（同 v2 §6.5，不可救）
誘答圖載入失敗            → 該格換入下一個未消耗的備援，格位不變
已被提示排除的格圖片失敗  → 不替換（該格已不參與作答）
備援耗盡仍有誘答圖失敗    → 該題作廢
```

- 備援**只能消耗一次**，替換是格位原子操作（選項身分與 `src` 同步更新）
- 多格同時失敗依失敗事件到達順序序列化處理

**不選**：誘答圖失敗就留空、改成三選一。缺格本身是可利用的線索
（使用者會推論「壞掉那格不是答案」，等同免費刪去一個誘答），
且該題與其他題權重不同卻同樣計 1.0 分。

**不選**（Codex 建議的替代案）：整題換掉。L2 的題幹就是藥名，
在使用者已讀完題幹後換題等於換題目，體驗更差，且與遞補邏輯耦合。

### D16 — 提示機制三級不同，滿分一律降為 0.5

| 級別 | 提示 | 理由 |
|---|---|---|
| L1 | **無提示按鈕** | 四選一 + 外觀明顯不同，再給提示等於送分 |
| L2 | 「刪去一個錯誤選項」（4 → 3） | 與 L3 對稱：降低難度換 0.5 分 |
| L3 | **不變**，沿用 v2 §6.3：首字母 + 底線 + 字元數 + 詞數（`makeHint()` 現行輸出） |

- 刪去的必須是**誘答**，絕不刪正解
- 刪去的格**保持可見並標示為已排除**，但**不可點選、不可鍵盤聚焦**——
  「保持可見」不等於「仍可作答」
- 已排除的格**不參與備援替換**（D15）
- 同一次 hint 事件**只決定一次**排除格並持久保存；重複點提示不重複扣分、
  不新增第二個排除格（沿用 v2 §6.4 狀態機）

### D17 — 誘答生成放 engine.js，pool 與管線零改動

| `data/pool.json` | **不動**，`schema` 維持 `1` |
| `tools/*` | **不動** |

**紀律**：本次變更**不得**觸及 `normalize()`。A17 為此設了可證偽的斷言（F5）。

### D18 — 身分鏈：一題只有一個紀錄身分

**這是本專案最高風險（答案與圖片錯配）的直接入口，必須寫死。**

抽樣單位是**答案鍵**，但題目的一切內容來自**單一紀錄（Item）**：

```
答案鍵 ans
  └─ 由 drawQuiz 在該 ans 的全部紀錄中均勻抽 1 筆 → correctItem（v2 D5，不變）
       ├─ L1/L3 的題目圖片      = correctItem.img
       ├─ L2 的題幹 full + zh   = correctItem.full / correctItem.zh
       ├─ L2 的正解格圖片        = correctItem.img
       ├─ options[answerIdx]     ≡ correctItem（同一物件，非同 ans 的另一筆）
       └─ 逐題檢討顯示的正解     = correctItem
```

**硬不變量**：

| # | 不變量 |
|---|---|
| I1 | `options[answerIdx]` 必須是 `correctItem` **本身**，不得是同 `ans` 的其他紀錄 |
| I2 | L2 的題幹 `full`/`zh` 與正解格圖片必須來自**同一紀錄** |
| I3 | 每個選項、每個備援都保留其原始紀錄身分（`id` 為主鍵），替換時整體換掉，不得只換 `img` |
| I4 | 判定、提示、替換、檢討全部引用**同一份題目快照**；整數索引只是該快照內的位置，**不得作為跨渲染的身分** |
| I5 | 每格具備不可混淆的三元組：`(題目 token, 格位 token, 目前資產 identity)` |

**「答案鍵可用」的定義**：該答案鍵在該級為可用 ⟺ **`drawQuiz` 可能抽到的每一筆紀錄
都能組出合法題目**。不是「至少一筆可用」——後者會讓同一答案鍵有時可出題有時炸掉，
產生難重現的失敗。

**題目 token**：整卷生成時賦予的唯一序號，**遞補不重用**。
不可用「第幾題」當 token——遞補會使題號位移（C11 的直接原因）。

### D19 — 兩階段整卷生成（取代逐題抽＋失敗補抽）

**v3 原稿的問題**：H2 要求「選項不得等於本卷其他題的正解」，這需要**整卷資訊**；
但原稿寫成逐題組裝、`NO_DISTRACTORS` 時改抽下一個答案鍵——
**新正解會回溯破壞已完成題目的 H2**。且「抽到不可用才跳過」會讓誘答池大的
答案鍵被高估，違反 v2 D5 已聲明的「答案鍵均勻」。

**採用兩階段，並分離 eligibility 與隨機選擇**：

```
階段 1（純判定，不用 RNG）
  對該級計算「可用答案鍵集合」E
    L1：F1 條件；L2：F2 條件（含 §4.3 放寬階段）；L3：全部答案鍵
  |E| < QUIZ_SIZE → 拋 INSUFFICIENT_KEYS（不進階段 2）

階段 2（隨機，在 E 內）
  自 E 均勻抽 20 個答案鍵（partial Fisher–Yates）
  每個答案鍵自其紀錄均勻抽 1 筆 → correctItem（v2 D5）
  確定完整正解集合後，才逐題以「完整正解集合」為 excludeAns 組裝選項
  任一題組裝失敗 → 整卷重抽（最多 3 次），而非局部補抽
最後對整卷做一次全不變量驗證（H1–H4、I1–I5）
```

**`excludeAns` 語意寫死**：整卷 20 個正解答案鍵的集合，**包含本題自己的正解**
（本題正解由 `answerIdx` 佔位，誘答本就不得等於它）。

**均勻性紀律**：三級都是**在各自的 E 內等機率抽樣**。
不得讓重試次數、候選紀錄數或誘答池大小變成抽樣權重。

### D20 — 純函式紀律：索引與輸入不可變

`buildIndex()` 產生的 `PoolIndex` 與傳入的 `items` 在
`buildChoices()` / `drawLeveledQuiz()` 執行前後**內容與順序必須完全不變**。

**具體陷阱**：partial Fisher–Yates 若就地洗共享候選陣列，
同一 index 的後續題目會依呼叫歷史改變——固定 seed 重現性直接破功，
且只會表現為偶發的順序相依 flaky test。洗牌一律在複本上進行。

允許內部快取，但快取內容須與 RNG 結果無關且不得改變候選集合。

### D21 — L2 ready-gate 與載入逾時

**L2 何時可作答**：目前有效的四格**全部載入並解碼成功**後，題目才進入可作答狀態。
載入期間選項不可點選、提示按鈕停用、放大停用，並顯示載入指示。

**逾時（僅 L2）**：任一格自 `src` 設定起 **8 秒**未 `load` 也未 `error`，
視同該格資源失敗，走 D15 的替換／作廢路徑。

> 這是 ready-gate 的直接後果：沒有逾時，一張永久 pending 的圖會鎖死整題。
> **L3 不加逾時**——L3 無 gate，卡住的圖不阻止使用者作答（§1.2 已列為非目標）。

**「資源失敗」的完整定義（L2）**：HTTP/網路錯誤、`onerror`、解碼失敗、
零尺寸（`naturalWidth === 0`）、逾時。五者處置相同。

**LOCKED 後的圖片錯誤一律忽略**：不作廢、不替換、不改分數。
題目已鎖定，事後的資源事件不得回溯改變結果。

### D22 — 瀏覽器縮放是 L2 可解性的一部分，不得停用

G1 的判定建立在「使用者可以 pinch-zoom 看清刻字」之上（§0）。
這使縮放從**便利功能**升級為**可解性的前提**。

| 規則 | 內容 |
|---|---|
| **禁止** | `viewport` 的 `user-scalable=no`、`maximum-scale`（任何 <5 的值）、以及會攔截雙指手勢的 `touch-action` |
| 現況 | `index.html:5` 為 `width=device-width, initial-scale=1`，**已符合**，本次不需改動 |
| 為何要寫成規則 | 這類屬性常為了「像 app 一點」而被順手加上，且**加了之後畫面完全正常**——只有 L2 會靜默變成不可解。沒有測試守住就必然回歸 |

**連帶簡化**：§6.2 原本規劃的「點擊放大」不再是必要功能。
原生 pinch-zoom 已覆蓋同一需求，且不佔版面、不新增狀態、
不與 D15 的替換與 D16 的排除格互動。**點擊放大移出本次範圍**。

**已知上限（誠實標註）**：鏡像圖片長邊 640px。單格 160 CSS px 在 DPR 3 的手機上
已用掉約 480 device px，因此 pinch-zoom 約在 **1.3–1.5×** 就會用盡來源解析度，
再放大只是插值、不會出現新細節。縮放能救的是「渲染縮得太小」，
救不了「來源照片本身沒拍清楚」。

## 4. 誘答演算法規格

### 4.1 共用硬條件（L1、L2 皆適用）

正解 + **5 個誘答**（前 3 正式、後 2 備援）必須**兩兩**全數滿足：

| # | 條件 |
|---|---|
| H1 | 答案鍵（`ans`）兩兩相異 |
| H2 | 選項與備援的答案鍵不得屬於**本卷正解集合**（D19 的 `excludeAns`，本題正解除外） |
| H3 | 兩兩之間不構成 D13 的編輯距離 ≤1 或前綴包含關係 |
| H4 | 正解在 4 格中的位置**必須由 RNG 洗牌決定**，不得固定、不得由題號決定 |

> H4 不是形式條件。忘記洗牌會讓正解恆在第 0 格，且從畫面上不易察覺。
> 更危險的是 `answerIdx` 分布正常但 `options[answerIdx]` 不是正解（違反 I1）——
> 那會把正確圖片判成錯誤答案。A13 兩者都要斷言。

### 4.2 L1 誘答條件（外觀明顯不同）

除 H1–H4 外，每個誘答對正解：

```
誘答藥名的「所有紀錄」外觀聯集 ∩ 正解.shape = ∅
誘答藥名的「所有紀錄」外觀聯集 ∩ 正解.color = ∅
```

集合以 `pool.json` 已排序去重的陣列為準。多層錠／膠囊帽身有多個顏色值，
**只要有任一顏色相同即視為相交而排除**。

> **v3.3 加嚴**：比對對象是**該答案鍵所有紀錄的外觀聯集**，不是任一代表紀錄。
> L1 的排除邏輯是「我知道 IBUPROFEN 長怎樣，所以它不是這張圖」——
> 但 IBUPROFEN 有 20 筆不同外觀，只要其中一筆與正解相似，這個推理就不成立。
> 只比對代表紀錄會漏掉同名不同廠的其他外觀。
> **實測代價為零**：加嚴後仍是 3913/3913 全部可組題。

### 4.3 L2 誘答條件（外觀相似但可辨）

除 H1–H4 外：

```
誘答.shape 與 正解.shape 完全相同（同集合）
誘答.color 與 正解.color 完全相同（同集合）
D12 的 L2key 對正解與其他全部誘答皆相異
```

**放寬順序（僅 L2，固定順序，不可隨機）**：嚴格條件湊不滿 5 個誘答時——

1. 顏色改為「集合相交即可」（不必完全相同）
2. 仍不足 → **該答案鍵不屬於 L2 的可用集合 E**（D19 階段 1 即排除，不是抽到才跳過）

**永不放寬**：形狀完全相同、`L2key` 相異。
前者放寬使 L2 退化成 L1，後者放寬產生無解題目。

### 4.4 三種錯誤的分類（不可混為一談）

| 錯誤 | 判定時機 | 門檻 | 呈現 |
|---|---|---|---|
| `INSUFFICIENT_KEYS` | D19 階段 1 | **`\|E\| < 20 + 每題誘答數`**（L1 為 23、L2 為 25；L3 仍為 20） | 前端顯示明確錯誤，**不得開始考卷**（沿用 v2 C4） |
| `QUIZ_ASSEMBLY_FAILED` | D19 階段 2 | 整卷重抽 3 次仍失敗 | 前端顯示明確錯誤，不得開始考卷 |
| **品質紅線**（非執行期錯誤） | CI（A9） | L2 嚴格階段可用答案鍵 < 3000 | **測試紅燈**，由人工裁決；線上程式不因此拒絕開局 |

**這三者不是同一件事**：前兩者是「這台裝置這一次開不了局」，
第三者是「題庫品質退化了，該有人來看」。v3 原稿把「可用答案鍵 <100」
與 A9 的 `≥3000` 混在一起，會產生「CI 說不可發布、線上照常開局」的雙重語意。

> **v3.3 修正（實作時由測試抓出）**：`INSUFFICIENT_KEYS` 的門檻原本寫 `|E| < n`，**是錯的**。
> H2 禁止誘答等於本卷其他題的正解——當可用答案鍵**恰好等於 n**，
> 全部答案鍵都是正解，合法誘答數為 **0**，必然一題都組不出來。
> 寫成 `< n` 會讓程式通過檢查後才在組裝階段炸掉，錯誤訊息還會指錯方向
> （使用者看到的是「組裝失敗」，實際原因是「題庫太小」）。
> 正確門檻是 `n + 每題誘答數`，且這是**必要非充分**條件，
> 剩餘的組合失敗仍由 `QUIZ_ASSEMBLY_FAILED` 兜底。

### 4.5 engine.js 新增 API（純函式，可 `node --test`）

```js
export const Level = { L1: 'L1', L2: 'L2', L3: 'L3' };
export const CHOICE_COUNT = 4;
export const DISTRACTOR_COUNT = 5;      // 3 正式 + 2 備援（D15）
export const L2_LOAD_TIMEOUT_MS = 8000; // D21

/** 建索引。回傳物件視為不可變（D20） */
export function buildIndex(items): PoolIndex

/** 階段 1：純判定，不用 RNG。回傳該級可用答案鍵集合（D19） */
export function eligibleKeys(index, level): Set<string>

/**
 * 階段 2：為單一正解紀錄組裝選項。
 * @param {Item}   correct     必須是已抽定的紀錄本身（I1）
 * @param {Set}    excludeAns  整卷正解答案鍵集合（D19）
 * @returns {{ options: Item[], answerIdx: number, spares: Item[] }}
 *          options.length === 4；spares 僅 L2 非空
 * @throws  code = 'NO_DISTRACTORS'
 */
export function buildChoices(correct, index, { level, rng, excludeAns }): Choice

/**
 * 整卷生成（D19 兩階段）。
 * @throws code = 'INSUFFICIENT_KEYS' | 'QUIZ_ASSEMBLY_FAILED'
 */
export function drawLeveledQuiz(items, { level, n, rng }): Question[]

/** 選擇題判定。嚴格整數相等，不經 normalize，不做型別轉換（A14） */
export function judgeChoice(pickedIdx, answerIdx): boolean

/** D16：回傳要排除的誘答格 index（絕不等於 answerIdx） */
export function pickEliminated(question, rng): number

/** D15：消耗一個備援替換指定格，回傳新題目狀態 */
export function replaceOption(question, slotIdx): Question
```

`transition()` / `newQuestion()` / `scoreQuiz()` 的**既有語意與參數不變**——
狀態機的 `submit` / `hint` / `fail` 對三級語意一致。
`scoreQuiz()` 僅新增回傳欄位（基線加總），**不新增參數、不需知道 level**（D14）。

### 4.6 效能

題庫 3913 筆。載入後建一次索引（`Map<shapeKey#colorKey, Item[]>`、`Map<ans, Item[]>`），
eligibility 判定為一次全掃，每題誘答挑選在候選陣列**複本**內做 partial Fisher–Yates。
20 題總計遠低於一次渲染成本。**不需**預先算進 pool。

### 5.1 QuizSession

| 欄位 | 性質 | 說明 |
|---|---|---|
| `level` | 不可變 | 建立時決定，**必須等於使用者在畫面上選的級別**（C7） |
| `questions` | 陣列 | 見 5.2 |
| `idx` | 作答狀態 | 目前題號 |
| `voided` | 作答狀態 | 累計作廢數（>3 中止，沿用 v2 §6.5） |

| `nextToken` | 內部 | 題目 token 產生器，**遞補不重用**（D18） |

### 5.2 Question（`newQuestion()` 回傳值的 v3 擴充）

| 欄位 | 性質 | L1 | L2 | L3 |
|---|---|:-:|:-:|:-:|
| `token` | **不可變身分** | ✓ | ✓ | ✓ |
| `item` | **不可變**（＝ `correctItem`，D18） | ✓ | ✓ | ✓ |
| `state` / `correct` / `mark` | 作答狀態（v2 狀態機，不變） | ✓ | ✓ | ✓ |
| `chance` | 作答狀態（D14，建題與提示時決定） | 0.25 | 0.25→0.1667 | 0 |
| `options` | **不可變**（4 個，`options[answerIdx] ≡ item`） | ✓ | ✓ | — |
| `answerIdx` | **不可變** | ✓ | ✓ | — |
| `spares` | 作答狀態（消耗式，僅 L2） | `[]` | ✓ | `[]` |
| `picked` | 作答狀態（使用者選的格） | ✓ | ✓ | — |
| `eliminated` | 作答狀態（提示排除的格，至多 1） | — | ✓ | — |
| `slotAsset[]` | 作答狀態（每格目前資產 identity，I5） | — | ✓ | — |

**畫面衍生值（不得存於 Question）**：DOM index、`src` 字串、載入中旗標的 UI 表現。
`slotAsset` 存的是**紀錄身分**（`id`），不是 `src`。

**ownership 紀律**：不可變欄位在建題後**不得再寫入**；
作答狀態只能經 `transition()` 或 `replaceOption()` 修改；
畫面層不得持有跨渲染的索引（I4）。

## 6. UI 規格

### 6.1 級別選擇

`#start` 區塊在「開始測驗」上方加入三張級別卡（沿用既有 `.metric` 樣式）。
每張卡標明：題型一句話、亂猜基線、是否有提示。

**每次進入 `#start` 都重設為未選取**——包含首次載入、「再測一回」、
完成一回合後返回。避免沿用上次級別卻在成績卡上印出非預期的級別。

級別選定前，「開始測驗」**必須真正無法觸發**：`disabled` 屬性、
鍵盤 Enter、直接呼叫 handler 三條路徑皆不得建立 QuizSession（C7）。

手機（375px）下三張卡直向堆疊。

### 6.2 題目版面

| 級別 | 版面 |
|---|---|
| L1 | 沿用現行版面（圖 + `#qFeatures` 特徵格），輸入列換成 4 個選項按鈕（直向堆疊，全寬，實際可點區域 ≥44×44px） |

**L2 的特徵遮蔽是硬條件，且範圍大於「隱藏 `#qFeatures`」**：

- 該題的 `shape`／`color`／`score_mark`／`mark1`／`mark2`／`size` **實際值**
  不得出現在可見文字、`alt`、`title`、`aria-label`、放大 modal 或任何隱藏文字中
- **現行 `app.js` 的 `img.alt = "藥品外觀實拍圖：${shape}／${color}"` 若直接沿用，
  答案會寫在 alt 裡送分**——L2 的 `alt` 只能是不含特徵的中性描述（如「選項 1 藥品外觀」）
- C8 因此斷言 **accessibility tree**，不是只看可見文字

並顯示每個選項對應的品名（L2 用來把「名字 ↔ 長相」補完，這正是該級的學習點）。
