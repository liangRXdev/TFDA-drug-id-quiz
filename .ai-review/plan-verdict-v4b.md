## 結論

**不可直接動工。** 沒有 Blocker（D28 的組卷方向正確、與既有架構相容），
但有 **13 項 High**，其中 **AR-1／AR-2／AR-3 必須在寫第一行程式碼之前定案**——
它們是 session ownership 的資料模型與 UI 契約，寫錯要整段重來。

**修訂範圍**：D28、D29、D31 三條設計決策改寫，新增 **D33（M5 可見 UI 契約）**，
§6 驗收條件重新分組並改寫 A30–A35／C28–C31、新增 C34–C38，F8 數字更新，
§7 風險表的「排除位置記憶」改為「降低」。

**修訂後是否需要再審一次？** AR-1／AR-2 屬於「補上原本沒有的契約」而非「換掉既有架構」，
D28 的組裝模型完全不動。**判定：不需要第三輪規格審查**，但修訂後的規格
應在實作完成後由 `/codex-review` 的區塊 4（規格符合度稽核）逐條比對——
**規格審查通過不代表實作會遵守規格**，這道縫是本 repo 已經摔過的地方。
