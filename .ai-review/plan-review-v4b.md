結論：**有條件通過，建議先修規格再動工**。D28 的「固定錯題鍵集合 → 沿用既有組裝 → 既有整卷驗證器」方向正確，沒有 Blocker；但 session ownership、可見 UI 接線及跨層驗收仍有數個 High 缺口，若照現稿實作，仍可能出現「測試全綠但錯題再戰不可見／回到錯的原卷」的失效。

### CSS cascade／layout 依賴檢查

A30–A35、C28、C29、C31 **本身不需要 CSS cascade、media query 或 layout 幾何**。

C30 現稿也沒有明寫 CSS 斷言，但其「點擊」**不能證明控制項對真實使用者可見**；stub 可以點擊 CSS 永久隱藏的元素。因此：

- DOM 接線與 handler 行為可自動驗。
- 控制項的真實可見性若納入 M5 UI 契約，應採「HTML/CSS 靜態原始碼契約＋真實瀏覽器人工留檔」。
- 不應在 `_ui-harness.mjs` 上加入 `getComputedStyle`、media query 或幾何斷言。

## 4. 更簡單的替代方案

| 嚴重度 | 問題 | 為什麼現在不修之後會更貴 | 建議修法 |
|---|---|---|---|
| **無發現** | D28 的固定 K＋既有組裝器＋既有 validator 並非 over-engineering。 | 逐鍵或 retry 專用遞補反而會形成第二套組裝模型。 | 維持現方案。 |
| **High** | `origin` 同時保存 questions、level 與未窮舉的「結算衍生值」比必要狀態更多。 | 每多保存一份衍生值，就多一個與重新計算結果分歧的來源。 | 更簡單的相容方案是：origin 只保存重新產生原結算、檢討與成績卡所需的單一權威資料；retry session 完全可拋棄；返回一律重算。 |
