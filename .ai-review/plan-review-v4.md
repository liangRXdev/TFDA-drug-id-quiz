結論：**v4.0 尚不宜動工**。主要有 3 個 Blocker：

- M5 的逐鍵重建契約缺少「整卷正解集合」，無法在建構時保證 H2。
- 錯題複習遇到執行期圖片失敗時，既有遞補會抽入非錯題，直接違反「只重練本回合錯題」。
- C23／C25／C27 指定由現有 DOM stub 自動驗證，但該 stub 沒有 CSS cascade、media query 或 layout engine，會產生假綠燈。

| **High — C26** | 文字已更新但正解格標記延後、按鈕仍 disabled、元素由 CSS opacity 隱藏，都可能通過。延後工作也可排在 microtask 或 animation frame，而非 `setTimeout`。 | 使用者仍要等待或無法立即前進。 | 同 tick 驗正解格、判定、按鈕可見且可操作；並涵蓋 microtask、animation frame 與 CSS visibility/opacity 的最終可見性。 |
| **Blocker — C27** | stub 可固定回傳相同矩形而永遠通過。反之，真實 `getBoundingClientRect()` 會包含允許的 `transform`，可能把合法 scale 動畫誤判為 layout shift。 | 驗收同時可能假陰性與假陽性，必須整條重寫。 | 驗的是 document-flow 位移而非 transformed bounding box；在真實 layout 環境量測相鄰錨點／容器佔位，涵蓋動畫開始、進行中與結束後。 |
| **High — C28** | 複習期間只不呼叫 `setItem`，但可先污染記憶體中的最佳紀錄，等下一正常回合再寫入；非同步延後寫入也可能逃過測試。 | 最高分會在後續回合才被洗掉，難以追因。 | 複習前後比較持久化快照及記憶體衍生結果；清空所有排程後仍不得寫入。再跑一個正常回合，確認未受複習分數影響。 |
| **High — C29** | 直接保存原結算 DOM 字串、返回時回填即可通過，但底層原卷已被覆寫；成績卡或再次操作會使用複習卷。 | UI 表面正確，資料真相已丟失。 | 返回後重新產生成績卡並驗原級別／分數；再次開啟檢討時仍由原卷衍生，且原卷快照逐欄未變。 |
| **Medium — C30** | handler 可先清空原狀態或呼叫建構器，最後才因零錯題不建立複習卷；現有斷言只看結果。 | 全對後點按鈕可能破壞原成績。 | 三種入口前後比較原卷、結算 DOM、紀錄及模式完全不變，並斷言沒有啟動重建。 |
| **High — C31** | 修改既有 app shell 檔但不新增／改名資源，條件式斷言可直接跳過 CACHE 版本；新增 CSS 後即使沒列入 SHELL，也可能只驗版本而通過。 | 部署後才出現 shell 組合不一致。 | 每批交付明確驗 CACHE 版本；所有新增 app shell 資源必須出現在 install 清單並能由實際 fetch/install 驅動取得；資料路徑仍不得呼叫 `respondWith`。 |

此外，A23–A29 全部是 engine 層證據，卻沒有任何 C 條件證明 M1/M2 真正接到答題頁與結算頁。至少需要一條跨層驗收，同時證明：

- live streak 在每次答題、提示、VOID 後更新正確；
- 結算頁顯示最長 streak；
- 稱號由實際 level 與 score 查表取得，而不是固定文字；
- start 頁讀回並顯示紀錄。

這些都屬既有 M1–M3 目標，不是新增需求。

## 4. 更簡單的替代方案

| 嚴重度 | 問題 | 為什麼現在不修之後會更貴 | 建議修法 |
|---|---|---|---|
| **High** | `rankValue` 是多餘的第二套模型，且不能證明稱號的真實語意。 | 稱號表與序數日後必然漂移。 | 只保留一張固定二維稱號表；逐格驗確切輸出，並以級別標籤避免被理解為跨級資格。 |
| **High** | M5 新增逐鍵 public API，卻重新遇到 D19 已解過的整卷排除問題。 | 形成兩套題卷組裝模型。 | 沿用 D19 的兩階段概念：差異只在第一階段的正解集合由錯題鍵固定，而非隨機抽出。其餘不變量與驗證路徑共用。 |
| **Medium** | A32 以「100 次、至少 20 組、最高頻 30%」定義功能，門檻與候選組合數沒有規格依據。合法組合較少的鍵可能被錯判。 | 測試容易 flaky，題庫更新也可能無故轉紅。 | 改用 controlled RNG 證明多個指定排列可達、相同序列可重現、答案位置不固定；不以任意統計門檻代替功能性質。 |
| **Medium** | `pool` hash 若既不顯示、不比較、不做遷移，只是永久增加 schema 與驗證面。 | 每個 storage 邊界都必須處理一個無使用者價值欄位。 | 二選一：明訂紀錄區塊顯示／診斷其版本留痕；否則刪除該欄，仍符合「不做跨題庫換算」。 |
| **Medium** | 稱號是否進 PNG 尚未拍板，卻讓 C24 保留條件分支。 | Canvas 版面與驗收不能定稿。 | 最簡方案是稱號不進成績卡：維持既有專業判定、級別、分數與基線，降低截圖誤導及版面回歸面。若確定要進，則須在動工前轉為硬需求。 |
| **Medium** | M4 同時引入 keyframe、transition、reduced-motion 自動驗證與幾何量測，對「低干擾微動畫」而言證據鏈過重且目前不可執行。 | 會花大量成本建假 layout stub。 | 限定為顏色／邊框 transition 與單一 streak transform；DOM stub 驗同步資訊接線，真實瀏覽器留檔驗 reduced-motion 與 layout。 |
| **Low** | 單一 storage key 已足夠，不需要再以「原子性」合理化；localStorage 本身不提供跨分頁交易原子性。 | 文件會讓後續維護者誤以為已解決競態。 | 保留單一 key，但將理由改為 schema 集中、清除簡單；另明確聲明跨分頁採何種一致性語意。 |

整體上，M1、M3 的方向可保留；M2 應移除不可證偽的 `rankValue`；M4 必須重分自動與真實瀏覽器證據；M5 則需先回到 D19 的兩階段整卷模型並補齊複習模式的圖片失敗語意，才適合進入實作。
